# 애널리스트 기록 ICT 점수 재작성 (2026-08-22)

PR #169 가 `find_bos_choch` 의 이벤트 순서를 고쳤다. 그 전까지 저장된 ICT
점수는 "가장 최근 구조 전환"이 아니라 "마지막 스윙 쌍이 만든 전환"을 보고
계산된 값이다. `data/analyst_log*` 에 2년치가 그대로 남아 있어 다시 찍었다.

도구: `scripts/restamp_analyst_ict.py` (재실행 가능)

## 무엇을 건드렸나

`ict` 만. `chart` 는 손대지 않았다 — 야후가 배당·분할로 과거 수정주가를 계속
갱신해 지금 다시 계산하면 그날 화면에 뜬 값과 어긋난다. `quant`·`quant_pit` 은
시점 데이터라 되돌릴 수 없다. `verdict` 는 저장값에 **차이만 더했다**
(`+= w_ict × Δict`).

가중치는 오늘의 `ic_weights.json` 이 아니라 **그날 기록에서 최소제곱으로
되찾았다.** 가중치는 매주 바뀌므로 오늘 값을 소급하면 다른 날의 자가 된다.
실기록 20일 전부 잔차 ≤ 0.09 로 복원됐고, 기간 중 ICT 몫이 실제로 움직였다
(0.052 → 0.042).

## 재현 가능한 것만 덮어썼다

기록마다 **결함을 되살린 코드**로 다시 계산해 저장값과 같은지 먼저 봤다.
같으면 그날 입력이 재현된 것이므로 고친 값으로 덮어쓰고, 다르면 그대로 뒀다.

| | 건수 | |
|---|---|---|
| 다시 찍음 | **2,925** | 전체 ict 기록의 2.1% |
| 값이 같음 | 137,746 | 순서가 안 갈렸거나 갈려도 점수가 같은 날 |
| 재현 못 함 | 1,733 | 1.2% — 수정주가 갱신으로 구조가 달라진 자리 |
| 패널이 안 닿음 | 1,387 | 2026-08-17~21 (패널은 08-14 까지) |
| verdict 재계산 | 19 | |

재현율 **98.8%** (140,671 / 142,404). 바뀐 값의 폭은 **중위 50.0점 · 최대
50.0점** — 리뷰 때 잰 "갈리면 평균 49.4점"과 일치한다.

검사: 항목 단위로 git HEAD 와 대조해 **날짜·국면·종목 집합·슬러그 집합·
chart·quant·quant_pit 이 하나도 안 바뀌었음**을 확인했다.

## 성적표는 거의 안 움직였다

521일 기록 기준, 재작성 전 → 후:

| 지평 | IC | t | IC 적중률 |
|---|---|---|---|
| 1일 | −0.0002 → −0.0001 | −0.02 → −0.01 | 48.5% → 49.1% |
| 5일 | −0.0014 → −0.0013 | −0.11 → −0.10 | 50.1% → 48.9% |
| 21일 | +0.0107 → +0.0106 | +0.44 → +0.43 | 54.9% → 54.7% |
| 63일 | −0.0130 → −0.0142 | −0.34 → −0.38 | 54.9% → 54.3% |

**결론은 안 바뀐다** — ICT 애널리스트는 전에도 후에도 `|t| < 2.0` 이라 판정
불가다. 방향도 지평마다 엇갈린다(1일은 좋아지고 63일은 나빠진다). 2,925건이
뒤집혔는데 총계가 안 움직인 것은 뒤집힘이 무작위에 가깝다는 뜻이다.

기록이 옳아진 것이지 새로 알게 된 것이 있는 게 아니다.

## 안 한 것

- **최근 5거래일**(2026-08-17~21, 1,387건). 저장 패널이 08-14 까지라 봉이
  없다. 없는 봉으로 점수를 만들지 않는다. 패널이 늘어난 뒤 도구를 다시 돌리면
  덮인다(예상 영향 약 30건). 여기서 새로 받지 않은 이유는
  `price_panel.load_panel` 이 **공유 캐시 파일을 갱신**하기 때문이다 — 기록
  수리에 패널 갱신을 섞지 않는다.
- **`data/scalp_log`**(15분봉, 12일 3,312건). 같은 결함을 안고 있지만 15분봉을
  다시 받아야 재현된다. 야후가 60일치만 주고 종목이 275개라 재현 성공률을
  장담할 수 없다 — 별건.
- **`backfill_analyst_log.py` 재실행.** `analyst_log.write_days` 가 연도 파일을
  `"w"` 로 통째로 다시 쓴다. 그러면 사전등록 측정으로 쌓은 `quant_pit`
  128,879건이 같이 날아간다.

## 이 작업에서 한 번 틀린 것

검사를 만들 때 "결함을 되살린 코드"라며 **이미 고쳐진 함수를 다시 감쌌다.**
옛값이 아니라 새값을 재고 있었고, 그래서 첫 전수 실행이 `restamped 0` 을 냈다.
그때서야 드러났다 — 표본 검사(132건)에서는 "97% 일치"로 보여 오히려 통과한
것처럼 읽혔다.

**옛 동작을 재현하려면 옛 코드의 사본이 필요하다.** 지금 함수의 출력을
후처리해서 옛 순서를 되살릴 수는 없다 — 정렬은 정보를 버리는 연산이다.
그래서 `legacy_find_bos_choch` 를 f0ae0d9 에서 통째로 베껴 두고
`sorted(옛것) == 지금것` 을 테스트로 잠갔다.

# 자동 인덱스 운용 시스템(A) — 설계

- 날짜: 2026-08-13
- 지시: "이기려는 걸 포기한 시스템을 만든다. 매수보유를 실행하는 프로그램."
- 대상(신규): `modules/index_autopilot.py`, `index_runner.py`,
  `.github/workflows/index-autopilot.yml`, `scripts/measure_index_autopilot.py`
- 대상(재사용): `modules/virtual_broker.py`, `modules/fx.py`, `modules/tax_kr.py`,
  `modules/price_panel.py`, `data/etf_panel.parquet`
- 근거 실측: `docs/measurements/` 의 PR #96·#99·#101 3연속 결과 —
  스윙 전략(연 +5.6%) < 같은 노출 매수보유(+10.3%) < 매수보유 100%(+19.5%),
  자산배분 규칙(GTAA 5 +4.4% / GEM +9.3%) < SPY 100%(+11.2%, 19.6년)

## 1. 왜

이 저장소는 네 번 수익률 예측에 실패했고, 세 번의 독립 측정이 전부 같은 답을
냈다 — **매수보유가 이긴다.** 매매로 수익을 내는 갈래는 2026-08-13 에 닫았다.

그런데 채널과 프로그램에는 **작동하는 결과물**이 필요하다. "성공이 나올 때까지
돌린다"로 가면 우연한 좋은 숫자를 성공으로 착각한다 — 이 저장소가 이미 겪었다
(+0.58R → 유령 체결).

그래서 성공을 둘로 쪼갠 것 중 **A** 다: 측정이 이미 준 답을 **실행하는
시스템**. 알파를 주장하지 않으므로 알파 검증 게이트에 걸리지 않고, 만들면
확률 100% 로 작동한다. 서사도 이쪽이 세다 — "이기려는 걸 포기하자 프로그램이
작동했다."

## 2. 무엇을 하는가

매달 정해진 날, 정해진 금액을, 목표비중에서 **가장 부족한 자산부터** 산다.
**절대 팔지 않는다.** 사람 손을 안 댄다. 매달 보고한다.

## 3. 사는 것

| 자산 | 티커 | 목표비중 | 2026-08-12 종가 | 총보수 |
|---|---|---|---|---|
| 미국주식 | ITOT | 70% | $169.57 | 0.03% |
| 채권 | AGG | 20% | $97.43 | 0.03% |
| 금 | GLDM | 10% | $87.33 | 0.10% |

### 3.1 왜 SPY·GLD 가 아닌가

**월 적립금으로 셋을 쪼갤 수 있어야 하기 때문이다.** 월 100만원은 환율
1,400 기준 약 $714 다. SPY 는 1주 $772.49, GLD 는 $404.92 라 한 주도 못 사거나
한 종목이 적립금 전부를 먹는다. ITOT·AGG·GLDM 은 전부 $200 아래다.

**소수점 매수는 쓰지 않는다.** 증권사마다 지원 여부와 체결 방식이 갈리고,
모아서 처리하므로 "다음 거래일 시가" 체결 가정이 흐려진다. 어디서든 걸 수 있는
정수주 주문만 낸다 — 백테스트 체결은 걸 수 있는 주문이어야 한다는 원칙
(2026-08-12, 유령 체결 사고)이 실운용에도 그대로 적용된다.

부작용: `SPLG` 는 후보에서 뺐다. yfinance 가 가격을 주지 못한다(2026-08-13
확인, `possibly delisted; no price data found`). 데이터 소스가 못 주는 티커는
쓸 수 없다.

### 3.2 비중 70/20/10 은 튜닝하지 않는다

이 숫자는 설계자가 원칙(주식 중심 + 채권·금으로 낙폭 완화)으로 골랐고
**백테스트로 고르지 않았다.** 나중에 성적이 나쁘다고 비중을 바꾸면 그것이
이 저장소의 여섯 번째 실패다. 변경하려면 사전 등록 4규칙(가설·판정선을 재기
전에 적기 / OOS 고정 / 벤치마크 동반 / 실패해도 발행)을 통과해야 한다.

## 4. 규칙 (전부)

```
매달 첫 거래일:
  가용현금(USD) = 적립금 원화 / 환율 × (1 − 환전스프레드)
                + 이월현금
                + 배당(원천징수 15% 차감 후)

  목표총액 = 현재 평가액 + 가용현금
  자산별 부족분 = 목표총액 × 목표비중 − 현재 평가액

  부족분이 큰 순서로, 가용현금이 허락하는 만큼 정수주 매수
    - 부족분이 음수인 자산은 건너뛴다 (매도 없음)
    - 1주 값이 남은 현금보다 크면 건너뛴다
  쓰고 남은 현금은 이월

체결: 다음 거래일 시가 (virtual_broker 기존 규칙)
```

밴드 없음. 리밸런싱 매도 없음. 레짐 필터 없음. 큰 폭락 뒤에는 규칙이 알아서
싸진 자산을 더 산다.

### 4.1 이월 현금이 청크 문제를 푼다

GLDM 목표분($71)이 1주 값($87)에 못 미치는 달이 자주 생긴다. 그 달은 안 사고
이월한다. 두 달이면 $142 가 모여 1주를 산다. 비중은 몇 달 주기로 목표에
수렴하고, 이 지연 자체가 실제 적립식이 가진 마찰이므로 감추지 않고 보고한다.

## 5. 구조

### 5.1 신규

**`modules/index_autopilot.py`** — 4장의 규칙 하나. 순수 함수다.
파일도 네트워크도 건드리지 않는다.

```
plan_orders(holdings, prices, cash_usd, targets) -> list[dict]
    holdings: {ticker: qty}
    prices:   {ticker: price_usd}
    cash_usd: 이번 달 가용현금
    targets:  {ticker: weight}   합 1.0
    반환:     [{"ticker","qty","est_price"}, ...]   qty 는 항상 양수
```

부수효과가 없으므로 `demo()` 자체검사로 전부 덮인다.

**`index_runner.py`** — 월 1회 러너. 환율 조회 → 가격 조회 →
`plan_orders()` → 가상 장부 주문 → 월 보고 발송. `paper_trade_runner_toss.py`
가 아니라 새 파일이다. 그 러너는 트레이드 플랜 전용이고, 규칙이 다른 두
시스템을 한 파일에 넣으면 성적이 섞인다.

**`.github/workflows/index-autopilot.yml`** — 매월 1~5일 매일 cron 으로 깨우고,
러너가 **그 달에 이미 적립했는지를 장부에서 보고** 안 했으면 실행한다. cron 은
휴장일을 모르므로 "첫 거래일"을 cron 식으로 표현할 수 없다. 클라우드 러너로
충분하다(브로커 API 를 부르지 않는다).

**`scripts/measure_index_autopilot.py`** — 과거 적립 시뮬 + 벤치마크 줄.
용도는 6장 참조.

### 5.2 재사용 (새로 짜지 않는다)

| 부품 | 쓰는 이유 |
|---|---|
| `modules/virtual_broker.py` | 다음 거래일 시가 체결·장부 누적이 이미 있다 |
| `modules/fx.py` | `fetch_krw_per_usd()` |
| `modules/tax_kr.py` | `OverseasStockLedger`(취득단가), 미실현 양도세 표시 |
| `modules/price_panel.py` + `data/etf_panel.parquet` | 측정용 패널. ITOT·GLDM 추가 |

### 5.3 장부를 분리한다

`VIRTUAL_PORTFOLIO_FILE=index_portfolio.json` 으로 **스윙 장부와 파일을
나눈다.** 기존 `virtual_portfolio.json` 은 공개 성적표(트레이드 플랜)의
근거다. 여기에 인덱스 매수가 섞이면 두 시스템의 성적을 영영 분리할 수 없다.
`virtual_broker.STATE_FILE` 이 이미 환경변수를 읽으므로 코드 변경은 없다.

## 6. 비용 — 0으로 두지 않는다

| 항목 | 기본값 | 근거 |
|---|---|---|
| 환전 스프레드 | 편도 10bp | 증권사 환율우대 90% 기준 |
| 매매 수수료 | 편도 25bp | 국내 증권사 미국주식 온라인, 보수적 |
| 배당 원천징수 | 15% | 미국 원천징수. 세후 금액을 재투자 |
| ETF 총보수 | 차감 안 함 | 이미 가격에 반영됨 |
| 양도세 | 0 | 매도가 없다. 대신 **미실현 양도세 부채**를 보고서에 표시 |

전부 환경변수 파라미터다. 이 저장소를 죽인 것이 비용 가정 하나였다
(왕복 40bp 가 신호를 0 으로 눌렀다, PR #94·#95). 판정에는 비용 가정을 반드시
같이 적는다.

배당은 AGG 수익의 사실상 전부다. yfinance `Ticker.dividends` 로 배당을 받아
세후 금액을 현금에 더한다. **마지막으로 반영한 배당일을 장부에 기록해** 러너가
두 번 돌아도 같은 배당이 두 번 들어가지 않게 한다(월 1~5일 반복 기동이
전제이므로 멱등성이 필수다).

## 7. 성공 판정 — 지금 못 박는다

측정하기 **전에** 적는다. 1년(12회 적립) 뒤 판정.

1. **무인 가동률** — 12개월 동안 사람 개입 0회, 월 보고 12회 전부 발행.
   실패 정의: 러너가 실패해 사람이 손으로 고친 달이 1회라도 있으면 미달.
2. **추적오차** — 같은 날 같은 금액을 **ITOT 100%** 에 넣었을 때의 곡선 대비
   연 **−0.5%p 이내**. 이기는 것이 아니라 **새지 않는 것**이 기준이다.
   비용·세금·정수주 체결지연이 얼마를 갉아먹는지가 이 한 줄에 드러난다.

절대 수익률은 판정 기준이 **아니다.** 시장이 정하는 값이고, 이 저장소가
이미 네 번 속은 기준이다.

벤치마크 줄은 매달 보고서에 같이 나간다.

## 9. 검증

**`modules/index_autopilot.py` 의 `demo()`** — assert 기반 자체검사.
프레임워크 없음.

- 매도 주문 0건 (모든 qty > 0)
- 목표비중 합 1.0 검사
- 정수주만 (qty 가 int)
- 주문 총액 ≤ 가용현금, 이월현금 ≥ 0
- 부족분이 큰 자산이 먼저 채워지는지
- 1주 값이 남은 현금보다 크면 건너뛰고 이월되는지
- 폭락 시나리오: 한 자산이 반토막 나면 그 자산이 우선순위 1위가 되는지

**`scripts/measure_index_autopilot.py`** — ETF 패널로 과거 적립 시뮬.
**성공을 찾는 최적화가 아니다.** 규칙이 적힌 대로 도는지와 마찰(정수주 지연·
비용·환전)의 크기를 재는 용도다. 벤치마크 줄(ITOT 100% 동일 적립)을 처음부터
같이 낸다.

GLDM 은 2018년 상장이라 그 이전 구간은 **GLD 로 대체**하고 그 사실을 표에
적는다(같은 금 현물, 총보수만 다름). 대체 사실을 숨기면 표본 길이를 속이는
것이 된다.

## 10. 명시적으로 안 하는 것

- **실제 돈** — 가상 장부로 1년 먼저 돈다. 실주문 경로는 PR #98 에서 지웠고,
  붙일 일이 생기면 Alpaca 전환 중단 사유를 먼저 다시 읽는다.
- **매도** — 리밸런싱 매도, 손절, 익절 전부 없다.
- **밴드 이탈 감시** — 매일 "벌어졌나"를 보는 로직을 넣지 않는다.
- **비중 튜닝** — 3.2 참조.
- **레짐 필터·노출 조절** — PR #99 에서 닫힌 갈래다(판정 주기만 바꿔도
  6.5%p 가 움직였다. 잰 것은 신호가 아니라 마찰이었다).
- **국내 상장 ETF** — 원화·절세계좌 이점이 있지만 이력이 짧고 데이터 소스를
  새로 붙여야 한다. 실제 돈 단계에서 다시 본다.

## 11. 운용 가정

- 월 적립 100만원, 시작 자본 0원 (`INDEX_MONTHLY_KRW`, 환경변수)
- 적립일: 매월 첫 거래일
- 통화: 원화 적립 → USD 환전 → 미국 상장 ETF 매수

# 검출력을 실제 두 바구니로 계산한다 — 설계

2026-08-16. `2026-08-15-fscore-longshort-design.md` 의 후속이고, **측정이 아니라 자를
고치는 건이다.** 새 가설도 새 데이터도 없다.

바로 앞 측정(`docs/measurements/2026-08-15-fscore-longshort.md`)에서 검출력 게이트가
**3.5배 빗나갔다.** 사전 등록이 "MDE 5.56%p, 게이트 통과"라고 적었는데 실측 반폭은
19.73%p 였다. 그 전 측정(`2026-08-14-fscore-smallcap.md`)에서도 "종목 수가 아니라
기준선 변동성"이라는 교훈을 적어놓고, **같은 함정의 다음 칸을 밟았다.**

두 번 틀렸으면 자를 고칠 차례다.

---

## 0. 무엇이 틀렸나 — 자가 아니라 입력이었다

`excess_cagr_ci`(`scripts/measure_pead.py:245`)의 블록 부트스트랩은 **두 줄을 같은
날짜로 묶어** 재표본한다. 즉 두 바구니의 상관은 처음부터 그대로 들어가고 있었다.
상관을 추정하는 코드를 새로 쓸 필요가 없다.

틀린 건 **거기에 넣은 두 줄**이다. `scripts/pilot_longshort_power.py:106` 은 게이트를
내기 위해 `shuffle_scores(ev)` 로 만든 **위약** 두 다리를 넣는다. 달 안에서 점수를
섞으면 고점수 바구니와 저점수 바구니가 **같은 풀에서 뽑은 거의 같은 포트폴리오**가
된다. 그 둘의 차이는 구조적으로 얌전할 수밖에 없다.

| | 위약 두 다리 | 실제 두 다리 |
|---|---|---|
| 두 다리의 상관 | 0.956 | 0.849 |
| 일별 스프레드 sd | 47.2bp | 99.1bp |
| MDE (95% 반폭) | 5.56%p | **19.73%p** |

셋째 줄의 3.5배는 첫째 줄에서 나온다. 진짜로 나눈 두 바구니는 업종·베타·시총이
다른 서로 다른 포트폴리오고, 그만큼 차이가 출렁인다.

**이 함정은 스프레드 설계에만 있다.** 소형주 롱온리에서는 위약 MDE 18.67 이 실제
반폭 16.39 보다 오히려 컸다 — 기준선이 전체 지수라 위약이 두 줄을 붙여놓지 않는다.
그래서 "위약 MDE 를 쓰지 말라"가 아니라 **"두 다리를 같은 풀에서 뽑는 설계에서는
위약 MDE 가 구조적 하한이다"** 가 맞는 문장이다.

## 1. 고치는 방법 — 실제 두 줄을 넣되, 평균은 안 본다

> 검출력은 **진짜 점수로 만든 두 바구니**의 일별 수익 두 줄로 계산한다.
> 그 두 줄에서 읽는 것은 **구간의 폭뿐**이고, 점추정·누적수익·부호는 읽지 않는다.

이건 사전 등록 위반이 아니다. 임상시험의 **눈가림 표본수 재계산**(blinded sample
size re-estimation)과 같은 장치다 — 효과 크기는 가린 채 **방해 모수(분산)만** 실측
으로 채운다. 폭은 효과의 방향도 크기도 알려주지 않는다.

**눈가림을 말이 아니라 구조로 강제한다.** 게이트를 내는 함수는 점추정을 **반환하지
않는다**:

```python
def mde_pp(strat, base):
    """② 추정량의 95% 반폭 = 이 설계가 잴 수 있는 최소 효과(연 %p).

    점추정을 반환하지 않는다 — 사전 등록 단계에서 결과를 볼 방법이 없어야 한다.
    """
    _, lo, hi = excess_cagr_ci(strat, base)
    return (hi - lo) / 2.0
```

사전 등록 스크립트는 `excess_cagr_ci` 를 직접 부르지 않고 `mde_pp` 만 쓴다.

**남는 새는 자리(적어둔다):** CAGR 은 `expm1` 을 거치는 비선형 변환이라 구간의 폭이
수준에 아주 약하게 딸려온다. 효과가 극단적으로 클 때만 문제이고, 지금까지 관측된
±20%p 범위에서는 무시할 수준이다. **완전한 눈가림이 아니라는 것을 알고 쓴다.**

## 2. 게이트는 10%p 그대로다

사장님 결정(2026-08-16). 새 자로 재면 지난 다섯 측정이 전부 게이트를 넘는데,
**그렇다고 게이트를 올리지 않는다.** 검사를 통과시키려고 기준을 옮기는 건 이
저장소가 이미 금지한 일이다.

게이트가 X 라는 건 "신호가 없다"가 아니라 **"이 설계로는 ②를 잴 수 없으니 돌리지
말라"** 는 뜻이다. 그때 할 수 있는 건 셋뿐이다: 창을 늘린다(√T), 추정량을 바꾼다,
아니면 **안 잰다**.

## 3. 첫 적용 — 지난 다섯 측정을 다시 채점한다

각 측정의 ② 신뢰구간 반폭이 곧 그 측정의 실제 MDE 다. **이미 발행된 숫자를 2로
나누면 나온다** — 재실행도 데이터 수급도 필요 없다.

> **정오표 (2026-08-16, 구현 중 발견).** 아래 표의 **마지막 두 행이 원 측정 문서와
> 어긋난다.** 이 절의 숫자는 기록으로 그대로 두고, **정정본은
> `docs/measurements/2026-08-16-power-rescore.md`** 다.
>
> - **소형주**: 실제 구간은 `[-8.41, +24.58]`(`2026-08-14-fscore-smallcap.md:18`)이라
>   MDE 는 **16.49**(16.39 아님), 사전 등록 MDE 는 **18.70**(18.67 아님)이다.
>   그리고 그 18.70 은 **위약이 아니라 기준선(매수보유) 줄만**으로 낸 값이다 —
>   소형주 롱온리 측정에는 위약 MDE 가 등장하지 않는다.
> - **롱숏**: `[-35.62, +3.85]` 는 ②가 아니라 **①(크기)** 행이다
>   (`2026-08-15-fscore-longshort.md:21`). 그 문서의 ②는 순열검정(`p = 1.000`)이라
>   **구간이 아예 없어 재채점 대상이 아니다.** 아래 "이번 재채점은 ②만 건드린다"도
>   그래서 롱숏에 대해서는 틀렸다 — 롱숏에서 다시 읽히는 것은 ① 이고, ②(p=1.000)는
>   그대로 산다.
> - 따라서 4절이 "하한"이라 부른 `mde_floor_pp` 도 하한이 아니다. 경계는 ρ=0.5 이고
>   **양방향으로 틀린다**(대형주 9.29 < 실제 11.94, 소형주 18.70 > 실제 16.49).
>   구현에서 `mde_baseline_pp` 로 개명했다 (PR #124).

| 측정 | ② 95% 구간 | 실제 MDE | 사전 등록이 주장한 MDE |
|---|---|---|---|
| PEAD (`2026-08-13-pead.md`) | [-11.10, +11.78] | **11.44** | — |
| F-Score 대형주 (`2026-08-14-fscore.md`) | [-21.08, +2.80] | **11.94** | 9.29 (O 였다) |
| quant-pit (`2026-08-14-quant-pit.md`) | [-19.79, +11.71] | **15.75** | — |
| F-Score 소형주 (`2026-08-14-fscore-smallcap.md`) | [-8.18, +24.60] | **16.39** | 18.67 |
| F-Score 롱숏 (`2026-08-15-fscore-longshort.md`) | [-35.62, +3.85] | **19.74** | 5.56 |

**다섯 건 전부 10%p 를 넘는다.** F-Score 대형주는 게이트를 통과했다고 적어놓고 실제로는
11.94 였다 — 사전 등록의 9.29 는 매수보유 줄만으로 낸 값이었다.

읽는 법:

- **②로 "실패"를 선언할 자격이 있었던 측정은 하나도 없다.** 다섯 건의 ② 판정은
  전부 "실패"가 아니라 **"미측정"** 으로 다시 적어야 한다.
- **①은 별개다.** F-Score 대형주의 IC t=-4.04 처럼 단면 검정으로 선 결론은 그대로
  살아 있다. 이번 재채점은 ②만 건드린다.
- **순열검정(②의 p값)도 그대로 산다.** 위약을 게이트로 쓰지 말자는 것이지 위약을
  버리자는 게 아니다.

산출물은 `docs/measurements/2026-08-16-power-rescore.md` 한 장이고, 각 원 측정 문서
맨 위에 **"이 문서의 ② 판정은 2026-08-16 재채점에서 미측정으로 바뀌었다"** 한 줄을
덧붙인다. 원 문서의 숫자는 한 글자도 안 고친다.

## 4. 바꾸는 코드 — 전부 합쳐 30줄 남짓

| 파일 | 무엇 |
|---|---|
| `scripts/measure_pead.py` | `mde_pp` 추가 (`excess_cagr_ci` 바로 아래, 4줄) |
| `scripts/pilot_longshort_power.py` | 자기 `mde_pp` 삭제하고 import. 셔플 줄은 **참고 하한**으로 강등, 게이트는 실제 두 줄로 |
| `scripts/measure_pead.py`·`measure_fscore.py`·`measure_fscore_longshort.py`·`measure_quant_pit.py` | 리포트에 MDE 한 줄씩 (각 1줄) |
| `tests/` | 자체검사 하나 (아래) |

**자체검사 — 이번 버그가 정확히 이 부등호를 위반했다.** 시장 데이터 없이 돈다:

```
같은 주변 분포(sd)를 갖되 상관만 다른 두 쌍을 만든다.
  ρ=0.95 (위약처럼 붙어 있는 두 다리)
  ρ=0.85 (실제처럼 갈라진 두 다리)
assert mde_pp(ρ=0.95) < mde_pp(ρ=0.85)
```

상관을 올리면 MDE 가 **줄어야** 한다. 위약이 MDE 를 작게 낸 이유가 바로 이거고,
`excess_cagr_ci` 가 날짜 짝을 안 맞추게 되는 순간 이 검사가 깨진다.

## 5. 안 하는 것

- **위약(셔플)을 지우지 않는다.** ②의 순열검정 p값은 위약 100개 위에서 계속 낸다.
- **상관을 따로 추정하는 코드를 안 쓴다.** 블록 부트스트랩이 이미 날짜로 짝을 맞춘다.
  ρ 는 문서에 적을 진단값이지 계산 경로에 들어가는 입력이 아니다.
- **①(IC) 쪽 검출력은 안 건드린다.** `block_t` 와 IC_BLOCK 은 그대로다.
- **다섯 측정을 재실행하지 않는다.** 발행된 구간을 2로 나눈다. 앞으로의 실행에는
  MDE 한 줄이 리포트에 박히므로 다음부터는 자동으로 나온다.

## 6. 이 문서가 틀릴 수 있는 자리

1. **눈가림이 완전하지 않다** — 1절 마지막 문단. `expm1` 비선형성으로 폭이 수준에
   약하게 딸려온다.
2. **"실제 두 줄"도 표본 하나다** — 관측된 그 구간의 변동성이지 모집단 변동성이
   아니다. 위약 20회 중앙값처럼 평균낼 대상이 없다. 대신 블록 부트스트랩 2,000회가
   그 안에서의 불확실성은 반영한다.
3. **게이트 10%p 자체는 여전히 임의값이다.** 이 문서는 게이트를 정당화하지 않는다 —
   게이트에 **올바른 입력**을 넣는 것까지만 한다.

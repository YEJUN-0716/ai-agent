# 성적표 공개 채널 — 설계

**작성일** 2026-07-28
**상태** 설계 승인됨 · 스펙 리뷰 대기
**선행** [2026-07-23-analyst-scorecard-design.md](2026-07-23-analyst-scorecard-design.md)

## 문제

`modules/analyst_scorecard.py` 는 애널리스트의 실측 성적을 낼 수 있다. 그런데
**재료가 3일치에서 멈춰 있다.** `data/analyst_log/2026.jsonl` 에는 07-23·24·25
세 줄뿐이다.

원인은 기록이 발송에 묶여 있기 때문이다. `analyst_log` 를 채우는 것은
`signal_worker.py` 인데, 이것을 돌리는 `.github/workflows/signal-alerts.yml` 은
2026-07-20 에 크론이 꺼졌다. 끈 이유는 정당하다 — 유니버스를 37→276 종목으로
넓혀 5년 walk-forward IC 를 재측정하니 전 팩터가 `|ICIR| < 0.1` 이었고,
`mom_3m` 은 +0.077 에서 -0.094 로 부호까지 뒤집혔다. 예측력이 확인되지 않은
신호를 매수 알림으로 보내지 않겠다는 판단이었다.

그 판단은 옳다. 문제는 **부작용**이다. 발송을 멈추자 기록도 같이 멈췄다.
지금 구조에서는 검증되지 않은 매수 알림을 켜야만 성적표의 재료가 쌓인다.
성적을 재려고 만든 로그가, 성적을 못 믿어서 멈춘 파이프라인에 인질로 잡혀 있다.

## 목표

기록을 발송에서 떼어내 매 영업일 쌓이게 하고, 채점 결과를 **공개 텔레그램
채널에 그대로 발행**한다. 틀린 성적을 포함해서.

**비목표(이번 범위 아님)**

- **매매 신호 발행.** 트레이드 플랜(`modules/trade_plan.py`)은 실측 기댓값
  +0.61R(롱 +0.69R, `docs/measurements/2026-07-24-trade-plan-short-vs-long.md`)로
  이 저장소에서 근거가 가장 단단한 자산이다. 그러나 진입가·손절가는 그 자체가
  매매 신호이고, 유료화 시 유사투자자문업(자본시장법) 신고 대상이 된다. 1차
  발행 범위에서 제외한다.
- **성적에 따른 가중치 자동 조정.** 선행 스펙의 비목표를 그대로 승계한다.
- **수익화.** 채널은 무료로 시작한다. 과금 설계는 구독자와 판정 표본이
  쌓인 뒤 별도로 다룬다.

## 설계 원칙

**기록과 발송을 분리한다.** 기록기는 아무것도 보내지 않고, 발행기는 아무것도
계산하지 않는다. 이 분리가 이 설계의 전부다. 둘이 붙어 있어서 지금 고장났다.

**나쁜 성적을 지우지 않는다.** 알파가 없다고 판정된 `quant` 애널리스트를
성적표에서 빼면 이 채널은 그냥 또 하나의 리딩방이 된다. 계속 기록하고 계속
나쁜 점수를 발행한다. 이것이 유일한 차별화 지점이다.

## 1. 기록기

매 영업일 미국 장마감 후, 276종목 × 애널리스트 3종(`chart`·`quant`·`ict`)의
점수를 `data/analyst_log/YYYY.jsonl` 에 한 줄로 적재한다. **텔레그램을 호출하지
않는다.**

한 줄의 형태는 지금과 같다:

```
{"date": "2026-07-23", "regime": "bull",
 "scores": {"AAPL": {"chart": 73.8, "quant": 51.0, "ict": 100.0}, ...}}
```

`modules/analyst_team.py` 의 `ANALYST_SLUGS` 는 `("chart", "quant", "ict")` 인데
현재 로그에는 `chart`·`ict` 두 키만 들어 있다. 구현 1단계에서 `quant` 가
누락되는 경로를 찾아 고친다. 알파가 없는 것과 기록하지 않는 것은 다르다 —
없다는 사실 자체가 발행 대상이다.

**스케줄** 22:30 UTC, 월~금. 기존 `signal-alerts.yml` 과 같은 시각이되, 별도
워크플로로 분리한다. `paper-trade-us`(21:30 UTC) 완료 후다.

`signal-alerts.yml` 은 지금처럼 `workflow_dispatch` 전용으로 남긴다. 매수
알림을 되살리는 것은 이 설계의 범위가 아니다.

## 2. 채점기

`analyst_scorecard.py` 를 그대로 쓴다. 기록일 + N영업일(N ∈ 5·21·63)이 지났고
아직 채점되지 않은 건을 찾아 순위상관(IC)과 Newey–West 표준오차를 낸다.

채점은 두 층이다. 섞으면 통계가 틀린다.

**1층 — 일별 단면 IC.** 기록일 하나에 대해 애널리스트 점수와 N일 후 수익률의
순위상관을 낸다. 결과는 `data/analyst_log/scores_YYYY.jsonl` 에 한 줄씩 쌓는다:

```
{"scored_at": "2026-07-30", "record_date": "2026-07-23",
 "horizon": 5, "analyst": "chart", "ic": -0.03, "n_tickers": 276}
```

(값은 형태를 보이기 위한 합성 예시다.) `record_date` + `horizon` + `analyst`
조합이 이미 있으면 다시 채점하지 않는다. 이것이 중복 발행을 막는 유일한
장치다.

**2층 — 누적 성적.** 1층 원장의 IC 계열을 애널리스트·지평별로 평균 내고,
여기에 Newey–West 표준오차를 적용한다. 자기상관 보정이 필요한 곳은 여기다 —
매일 기록한 5일 예측은 선행 구간이 서로 겹치므로, 겹친 관측을 독립으로 세면
표본이 실제보다 몇 배 많아 보인다. `analyst_scorecard.py` 의
`newey_west_se(values, lag)` 에 IC 계열과 `lag = horizon - 1` 을 넘긴다.

2층은 파일에 쌓지 않고 발행할 때마다 원장에서 다시 계산한다. 원장이 유일한
진실이고 누적 성적은 그 함수이므로, 따로 저장하면 어긋날 자리만 생긴다.

**발행기와의 경계** 두 층 모두 채점기가 계산한다. 발행기는 숫자를 받아 문장으로
바꿀 뿐 어떤 통계도 내지 않는다.

첫 판정 도래는 07-23 기록의 5영업일 지평 — **2026-07-30 전후**다. 이때
1층 레코드는 1건이고, 2층 누적 성적은 표본 1개짜리라 표준오차를 말할 수
없다. 발행문에 IC 값과 함께 **"판정 표본 n=1, 통계적 판단 불가"** 를 명시한다.
표본이 적을 때 그 사실을 감추지 않는 것이 이 채널의 전제다.

## 3. 발행기

공개 텔레그램 채널에 매 영업일 1회 발행한다. `daily_report_toss.py` 의
`send_tg` 패턴을 재사용하되, 대상 채팅을 새 시크릿
`TELEGRAM_PUBLIC_CHANNEL_ID` 로 분리한다. 기존 `TELEGRAM_CHAT_ID`(개인 P&L
리포트)와 섞지 않는다.

**스케줄** 23:45 UTC = KST 08:45, 월~금. `daily-report`(23:30 UTC)와 15분
간격을 둔다. 채점기와 발행기는 같은 워크플로에서 순서대로 돈다 — 채점 후
발행이다. 워크플로 수준의 분리는 **기록(22:30) ↔ 발행(23:45)** 사이에만 둔다.

발행물은 세 종류다.

| 종류 | 언제 | 내용 |
|---|---|---|
| 오늘의 기록 | 매 영업일 | 애널리스트별 상위 5종목과 점수. 채점 대상을 못 박는 것이 목적 |
| 채점 결과 | 판정 도래일 | N일 전 예측의 IC·표준오차·판정 표본 수. 음수 IC 도 그대로 |
| 측정 노트 | 비정기 | `docs/measurements/` 의 실측 기록을 사람이 풀어 쓴 것 |

측정 노트는 초기 발행 공백을 메운다. 채점 표본이 쌓이기 전 몇 주 동안 발행할
것이 "오늘의 기록"뿐이면 채널이 비어 보인다. 첫 노트 재료는 이미 있다 —
276종목 확대 후 전 팩터 `|ICIR| < 0.1`, `mom_3m` 부호 반전.

**노출 범위** 채점은 276종목 전체로 한다(단면 상관이라 종목 수가 곧 정밀도).
발행은 애널리스트별 상위 5종목만 노출한다.

## 4. 규제 처리

발행물에 종목별 매수·매도·목표가 표현을 쓰지 않는다. 점수와 순위, 그리고 사후
채점 결과만 발행한다. 모든 메시지 하단에 고정 면책 문구를 붙인다.

> 이 채널은 예측 기록과 사후 채점을 공개합니다. 투자 자문이나 매매 권유가
> 아니며, 투자 판단과 그 결과는 본인에게 귀속됩니다.

문구는 발행기 상수로 두고 메시지 조립 시 항상 덧붙인다. 옵션으로 만들지
않는다.

## 5. 비용

| 항목 | 비용 |
|---|---|
| GitHub Actions | 무료 (공개 저장소 무제한 / 비공개 월 2,000분) |
| 텔레그램 채널·봇 | 무료 |
| 데이터(yfinance·DART) | 무료 |

추가 지출 0원. 제품의 코어가 팩터 계산과 통계 채점이라 사용자 요청당
추론 원가가 발생하지 않는다.

## 6. 사람이 해야 할 일

구현 전 사용자가 직접 처리해야 하는 것이 둘 있다.

1. 텔레그램 공개 채널 개설, 기존 봇을 관리자로 추가
2. 채널 ID 를 저장소 시크릿 `TELEGRAM_PUBLIC_CHANNEL_ID` 로 등록

## 7. 구현 범위

**새로 만드는 것**

- 기록 전용 진입점 (텔레그램 발송 없음)
- 채점 도래분 탐지 + `scores_YYYY.jsonl` 적재
- 발행기 (메시지 조립 + 공개 채널 발송)
- 워크플로 2개 (기록 22:30 UTC / 발행 23:45 UTC)

**그대로 쓰는 것**

- `modules/analyst_scorecard.py` — 채점 산식
- `modules/analyst_team.py` — 점수 산식
- `daily_report_toss.py` 의 `send_tg` — 발송 패턴

**고치는 것**

- `quant` 애널리스트가 `analyst_log` 에 기록되지 않는 경로

## 8. 성공 판정

- 기록이 매 영업일 자동으로 쌓인다 (연속 10영업일 결손 0)
- 첫 5일 지평 채점 결과가 채널에 발행된다
- 발행 실패 시 조용히 넘어가지 않고 워크플로가 실패로 끝난다

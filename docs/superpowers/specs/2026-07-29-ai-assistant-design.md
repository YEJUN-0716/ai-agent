# AI 업무 비서 챗봇 — 설계

작성일: 2026-07-29
상태: 승인 대기

## 1. 무엇을 만드는가

사장님 개인 업무 비서 챗봇. 텔레그램(휴대폰)과 PC 브라우저 양쪽에서 같은 비서에게 말을 건다.
비서는 대화만 하는 게 아니라 도구를 꺼내 실제 일을 한다.

최종적으로 붙일 도구는 넷:

1. 주식 분석 질의 (**1단계 — 이번 범위**)
2. 옵시디언 볼트 검색·기록
3. 학업 자료 요약·분석
4. 일정·할일 관리

네 가지는 데이터도 인증도 실패 방식도 서로 다르다. 한 번에 만들면 어디가 고장났는지 알 수 없는 덩어리가 된다.
따라서 **비서 본체는 한 번 세우고, 도구를 하나씩 꽂는다.** 이 문서는 본체 + 주식 도구까지를 다룬다.

## 2. 결정 사항과 근거

| 결정 | 선택 | 근거 |
|---|---|---|
| 만드는 방식 | 직접 만든 파이썬 서버 | 옵시디언 볼트도 주식 데이터도 로컬에 있다. 클라우드 에이전트를 쓰면 결국 로컬 중계 프로그램이 따로 필요해 서버가 둘이 된다 |
| 실행 위치 | 자택 PC (상시 가동) | stock-analyzer 러너 때문에 이미 상시 가동 중 |
| 창구 | 텔레그램 + PC 웹 | 카카오톡은 (a) 친구 채팅방 봇 API 없음 (b) 공개 HTTPS 주소 필요 (c) 응답 5초 제한. 외부 통로를 열지 않기로 결정 |
| 카카오톡 | **이번 범위에서 제외** | 위 (b) 때문. 창구 계층은 추가 가능하게 설계하되 구현하지 않음 |
| stock-analyzer 관계 | 읽기 전용 + 가상 브로커 쓰기 | 분석 결과는 읽기만. 관심종목·메모는 비서가 자기 파일로 소유 |
| 실제 주문 | **도구를 만들지 않음** | 없는 도구는 실수로 호출될 수 없다 |
| 모델 | `claude-opus-5` | 도구 선택과 다단계 추론이 핵심인 작업 |

## 3. 구조

```
[휴대폰 텔레그램] ─┐
                  ├─→ 비서 서버 (자택 PC)
[PC 브라우저]  ────┘         │
                             ├─ 두뇌: Claude API + 도구 호출 루프
                             ├─ 기억: SQLite (대화 기록)
                             └─ 도구함: tools/
                                    └─ stock_reader.py  ← 1단계
                                       (2단계 이후: obsidian / study / calendar)
```

### 파일 배치

기존 프로젝트 구조(`tools/`, `workflows/`)를 따른다.

| 경로 | 책임 | 의존 대상 |
|---|---|---|
| `server.py` | 실행 진입점. 텔레그램·웹 창구를 함께 띄운다 | channels/ |
| `assistant/brain.py` | 질문 → 도구 선택 → 답변. Claude API 호출 루프 | anthropic SDK, tools/ |
| `assistant/memory.py` | 대화 기록 저장·조회 | SQLite |
| `assistant/config.py` | `.env` 읽기, 경로·키 확인 | — |
| `channels/telegram_bot.py` | 텔레그램 입출력 | assistant/brain |
| `channels/web.py` | 브라우저 채팅 화면 (FastAPI) | assistant/brain |
| `tools/stock_reader.py` | **stock-analyzer와의 유일한 접점** | stock-analyzer 결과 파일 |
| `tools/assistant_notes.py` | 비서 소유 관심종목·메모 | `data/assistant/` |
| `workflows/ai-assistant.md` | 사용·확장 설명서 | — |

각 모듈은 자기 일만 하고 정해진 창구로만 대화한다.
텔레그램이 죽어도 웹은 돌고, 주식 도구가 죽어도 대화는 된다.

## 4. 주식 도구 — 경계 설계

### 원칙

stock-analyzer는 **건드리지 않는다.** 코드도 구조도 그대로 둔다.
접점은 `tools/stock_reader.py` 한 파일. stock-analyzer 폴더 위치는 `.env`의 `STOCK_ANALYZER_PATH`로만 안다.

이렇게 하는 이유: 나중에 stock-analyzer 구조가 바뀌어도 고칠 곳이 한 곳이다.
경로가 챗봇 여기저기 흩어지면 저쪽을 손댈 때마다 이쪽이 깨진다.

### 읽는 것 (stock-analyzer 소유, 절대 쓰지 않음)

| 대상 | 파일 |
|---|---|
| 가상 브로커 자본 곡선 | `equity_log.json` |
| 가상 브로커 보유 현황 | `virtual_portfolio.json` |
| 시그널 기록 | `signal_log.json` |
| 애널리스트 성적표 | `data/analyst_log/` |
| 발행 기록 | `data/publish_log/` |

정확한 필드명은 구현 단계에서 각 파일을 읽어 확정한다.

### 쓰는 것

**가상 브로커 매매** — stock-analyzer의 `modules/virtual_broker.py`가 이미 제공하는 창구를 호출한다.
`place_notional_buy` / `place_market_sell`로 주문을 예약하면 다음날 시가에 체결된다.
비서는 이 두 함수만 부르고 내부 상태 파일에 직접 손대지 않는다.

**관심종목·메모** — stock-analyzer에는 저장된 관심종목 목록이 없다(매일 점수로 자동 산출).
따라서 비서가 자기 파일을 소유한다.

```
data/assistant/watchlist.json
  [{"symbol": "AAPL", "added_at": "2026-07-29", "reason": "실적 발표 대기"}]

data/assistant/notes.json
  [{"symbol": "AAPL", "note": "가이던스 확인 후 재검토",
    "created_at": "2026-07-29T10:30:00+09:00"}]
```

날짜는 ISO 8601, 시각은 KST 오프셋을 포함한다.
stock-analyzer 폴더에는 아무것도 쓰지 않는다.

## 5. 기억

두 종류를 분리한다.

- **대화 기록** — SQLite 파일 하나: `data/assistant/conversations.db`, 테이블
  `messages(id, channel, role, content, created_at)`. 텔레그램과 웹이 같은 기록을 공유하므로
  폰에서 물어본 걸 PC에서 이어서 물을 수 있다.
- **비서 소유 데이터** — 관심종목·메모. 위 4절 참조.

대화가 길어져 한도에 가까워지면 앞부분을 자동 요약해 이어간다(API의 compaction 기능).
같은 설명문을 매번 다시 보내지 않도록 프롬프트 캐싱을 켠다.

## 6. 안전장치

### 되돌릴 수 있는지로 나눈다

| 행동 | 처리 |
|---|---|
| 관심종목 추가·제외, 메모 기록 | 바로 실행 |
| 가상 브로커 매수·매도 | **실행 전 사용자 확인 필수.** 확인 없이는 주문이 나가지 않는다 |
| 실제 돈 주문 | 도구 자체를 만들지 않는다 |

### 접근 통제

- 텔레그램: 허용된 chat_id에만 응답. 그 외 메시지는 무시하고 기록만 남긴다.
- 웹: localhost 바인딩. 외부에서 접근 불가.
- API 키·토큰: `.env`에만. 코드·워크플로·문서에 넣지 않는다. `.gitignore` 확인.

### 감사 기록

모든 쓰기 행동은 `data/assistant/audit.log`에 남긴다.

```
2026-07-29T10:30:00+09:00 | watchlist_add | AAPL
2026-07-29T10:31:12+09:00 | virtual_buy   | AAPL notional=1000000
```

"언제 뭘 바꿨는지"를 나중에 비서에게 물어볼 수 있다.

## 7. 실패 처리

원칙: **도구 하나의 실패가 비서 전체를 멈추지 않는다. 그리고 조용히 지어내지 않는다.**

| 상황 | 동작 |
|---|---|
| stock-analyzer 파일 없음·손상 | 도구가 사람이 읽을 수 있는 이유를 담은 오류를 반환. 비서가 그대로 설명하고 대화 계속 |
| Claude API 오류·한도 초과 | 자동 재시도 후, 그래도 실패하면 사용자에게 상황을 알림 |
| 텔레그램 연결 끊김 | 웹은 계속 동작. 재연결 시도 |
| 가상 매매 실패 | 실패 사유를 그대로 전달. 성공한 척하지 않는다 |

경계(사용자 입력, 외부 파일)에서는 값을 검증한다. 내부 코드끼리는 신뢰한다.

## 8. 비용

대화 한 번당 대략 50~150원(도구 호출 횟수에 따라). 하루 30회 기준 **월 5~10만원** 수준.
프롬프트 캐싱을 켠 상태의 추정치다. 더 줄여야 하면 `effort` 설정을 낮춘다.

## 9. 검증

가짜 stock-analyzer 데이터를 만들어 두고 진짜 파일 없이 검사한다.

- 각 읽기 도구가 정상 데이터·손상 데이터·파일 없음 상황에서 올바르게 동작하는가
- 관심종목·메모 쓰기가 저장되고 다시 읽히는가
- **가상 매매가 확인 없이는 실행되지 않는가** (안전장치의 핵심)
- 허용되지 않은 텔레그램 chat_id가 무시되는가
- 대화 기록이 텔레그램·웹 사이에서 공유되는가

목표 커버리지 80% 이상.

## 10. 이번 범위에서 제외하는 것

- 카카오톡 창구 (외부 통로 미개방 결정)
- 옵시디언 / 학업 자료 / 일정 도구 (2~4단계)
- 실제 증권 주문
- 여러 사용자 지원 (사장님 1인 전용)
- 비서가 먼저 말 거는 알림 기능 (기존 stock-analyzer 텔레그램 발행이 이미 담당)

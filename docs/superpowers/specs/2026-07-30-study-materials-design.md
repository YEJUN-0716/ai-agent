# 학업 자료 요약·분석 — 설계

작성일: 2026-07-30
상태: 승인됨
범위: 비서 2단계 (1단계 = 본체 + 주식 도구, 완료)

## 1. 무엇을 만드는가

사장님이 바탕화면 폴더에 PDF를 넣고 "정리해줘"라고 하면, 비서가 읽고 요약해서
옵시디언 볼트에 노트로 남긴다. 그 뒤로는 그 자료에 대해 물어볼 수 있다.

원하는 결과물 세 가지 (2026-07-30 확인):

1. **핵심 요약 노트** — 원본을 다시 안 열어도 되게
2. **쉬운 말로 설명** — 어려운 대목을 풀어서
3. **물어보면 답하기** — "3장 그 예시 뭐였지?"

시험 대비 문제는 만들지 않는다 (사장님이 고르지 않음).

## 2. 결정 사항과 근거

| 결정 | 근거 |
|---|---|
| 2단계로 **학업 자료**를 먼저 (옵시디언 검색보다) | 볼트에 사람이 쓴 노트가 3개뿐이다. 검색 도구를 먼저 만들면 검색할 게 없다. 자료를 쌓는 일이 먼저다 |
| 자료 전달은 **PC 폴더 드롭** | 폰 업로드 배관이 없어 고장날 곳이 적다. PDF는 대개 PC에 있다 |
| PDF를 **그대로** 비서에게 넘긴다 | Claude API가 각 페이지를 이미지로 변환해 텍스트와 함께 분석한다. 그림·수식·표를 본다 |
| **글자 추출 라이브러리를 쓰지 않는다** | `pypdf`는 글자만 뽑는다. 그림이 사라지고 수식이 깨진다. 논문·강의자료에서 그게 빠지면 요약이 껍데기가 된다 |
| 요약 노트는 **볼트**, 원본 PDF는 **처리완료 폴더** | 볼트는 사람이 여는 곳이다. 기계가 만든 원문을 쏟으면 3단계 검색 도구가 쓰레기를 뒤진다 |
| 원본을 **바깥에 저장하지 않는다** | Files API로 올려두면 재질문이 싸지지만 앤트로픽 서버에 남는다. 필요할 때만 보내는 쪽을 택한다 |
| **자동 실행하지 않는다** | 정리 1건에 2,000~3,000원이 든다. 사장님이 말할 때만 움직인다 |

## 3. 흐름

```
① 사장님: 바탕화면 "자료넣는곳"에 PDF를 끌어다 놓는다
② 사장님: 텔레그램에 "새로 넣은 거 정리해줘"
③ 비서:   PDF를 읽고 (그림·수식 포함) 요약을 쓴다
④ 저장:   볼트에 노트 / 처리완료 폴더로 원본 이동
```

### 저장 위치

| 어디 | 무엇이 | 누가 읽나 |
|---|---|---|
| `~/Desktop/자료넣는곳/` | 처리 대기 중인 PDF | 사장님이 넣는다 |
| `~/Desktop/자료넣는곳/처리완료/` | 정리 끝난 원본 PDF | 세부 질문 때 비서가 다시 연다 |
| `ObsidianVault/학업/` | 요약 노트 (`.md`) | **사장님** |
| 비서 데이터 폴더 `materials.json` | 자료 목록 | 비서 |

두 경로는 `.env`에서 바꿀 수 있다 — `STUDY_INBOX`(기본 `~/Desktop/자료넣는곳`)와
`OBSIDIAN_VAULT`(기본값 없음, 없으면 시작할 때 막는다). 볼트 경로는
`.env.example` 10행에 이미 주석으로 있다.

`처리완료`는 자료넣는곳 **안**에 있으므로, `list_new_materials`는 그 폴더를 건너뛴다.
안 그러면 이미 정리한 자료를 매번 다시 정리 대상으로 본다.

원본 PDF는 **어떤 경우에도 삭제하지 않는다.** 비서가 잘못 읽었을 때 복구할 수단이
원본뿐이다.

### 노트 형식

```markdown
---
source: 논문제목.pdf
ingested: 2026-07-30
material_id: a1b2c3d4
---

# 논문제목

## 한 줄 요약
## 핵심
## 쉬운 말로

---
원본 PDF는 처리완료 폴더에 있습니다. 세부 내용은 비서에게 물어보세요.
```

### 목록 파일 (`materials.json`)

```json
[
  {
    "material_id": "a1b2c3d4",
    "title": "논문제목",
    "one_line": "이 자료가 무슨 얘기인지 한 줄로",
    "source_file": "처리완료/논문제목.pdf",
    "ingested_at": "2026-07-30T14:05:22+09:00",
    "note_path": "학업/2026-07-30-논문제목.md"
  }
]
```

`pages`는 넣지 않는다. 미리 세려면 PDF 라이브러리가 필요한데 그것을 쓰지
않기로 했고, 600쪽 초과는 API가 알려준다.

`one_line`이 여기 있는 이유: `list_materials`가 어느 자료를 펼칠지 고를 때 쓴다.
노트 본문을 전부 읽어야 목록을 만들 수 있으면, 자료가 늘수록 목록 한 번 보는 값이
비싸진다. 노트에도 같은 문장이 들어가지만 목록의 것이 원본이다.

시각은 KST ISO-8601. 기존 `tools/assistant_notes.py`의 `load_json_list` /
`save_json_list`를 그대로 쓴다 — 손상 파일 보관 정책과 원자적 쓰기를 공유하기 위해서다.

## 4. 비서가 쓸 도구

| 도구 | 하는 일 |
|---|---|
| `list_new_materials` | 자료넣는곳에 무엇이 기다리는지 |
| `summarize_new_material` | PDF를 읽고 요약 → 노트 작성 + 원본 이동 + 목록 기록 |
| `list_materials` | 정리된 자료 목록 (제목 + 한 줄 요약) |
| `ask_material` | 보관된 원본 PDF를 다시 펼쳐 세부 질문에 답한다 |

> 구현하며 확정된 것: `tool_result`에는 문서 블록을 넣을 수 없어(텍스트와
> 이미지만 된다) 도구가 자기 API 호출로 PDF를 첨부한다. 그래서 읽기와
> 저장이 `summarize_new_material` 하나로 합쳐졌다.

요약을 **쓰는 것은 비서**다. 도구는 파일만 다룬다. 요약 품질은 비서가 책임지고,
파일이 깨지는 것은 테스트로 막는다.

### 질문에 답하는 방식

1. `list_materials`로 목록을 훑어 관련 자료를 고른다
2. **요약 노트로 답할 수 있으면 거기서 끝낸다** (거의 공짜)
3. 노트에 없는 세부 내용이면 그때만 `open_material`로 원본을 펼친다

자료가 수십 개로 늘어도 목록만 보고 필요한 것만 여니 감당된다.

## 5. PDF 처리

Claude API는 PDF를 **문서 블록**으로 받는다. 각 페이지를 이미지로 변환하고,
그 페이지에서 뽑은 텍스트를 이미지와 함께 모델에 준다. 그래서 차트·다이어그램·수식을
읽을 수 있다. 별도 베타 헤더가 필요 없다.

스캔한 PDF도 읽힌다 — 페이지를 그림으로 보기 때문이다. OCR 프로그램을 따로 깔지 않는다.

### 한도

| | |
|---|---|
| 요청 하나의 크기 | 32MB |
| 페이지 수 | 600쪽 |
| 안 되는 것 | 암호가 걸린 PDF |

넘으면 나눠 넣어달라고 알린다. 조용히 절반만 읽는 것보다 낫다.

### 비용

페이지당 텍스트 1,500~3,000 토큰에 더해, 페이지를 이미지로도 보므로 이미지 토큰이
추가된다. **100쪽 자료 1건 정리에 약 2,000~3,000원**으로 본다.

한 번만 내면 되는 값이다. 그 뒤 질문은 요약 노트만 읽으므로 훨씬 싸다.
자동 실행하지 않는 이유가 이것이다.

## 6. 실패 처리

| 상황 | 어떻게 |
|---|---|
| PDF가 아닌 파일 | 건너뛰고 알린다 |
| 32MB / 600쪽 초과 | 거부하고 이유를 말한다. 원본은 그대로 둔다 |
| 암호 걸린 PDF | 못 읽는다고 분명히 말한다. 빈 요약을 만들지 않는다 |
| **노트는 저장됐는데 목록 기록이 실패** | **둘 다 취소한다.** 반쪽만 남으면 나중에 조용히 틀린 답이 나온다 |
| 같은 이름 노트가 이미 있음 | 덮어쓰지 않고 번호를 붙인다 |
| 원본 PDF | 성공했을 때만 처리완료로 **이동**. 실패하면 자료넣는곳에 남아 다시 시도할 수 있다. **삭제하지 않는다** |

"반쪽만 저장" 항목은 2026-07-30에 대화기록에서 실제로 겪은 문제와 같은 원리다
(`assistant/memory.py`의 `append_exchange` 참고).

## 7. 검증

- **진짜 PDF로** 확인한다. 그림과 수식이 있는 것으로 (가짜로 때우면
  `test_broker_seam.py`가 잡아낸 것과 같은 종류의 결함이 새어 나간다)
- 목록 기록이 실패하면 노트도 안 남는지
- 한도 초과 PDF를 정말 거부하는지
- 실패 후 원본이 자료넣는곳에 남아 있는지
- 고친 뒤 **코드를 일부러 되돌려 테스트가 잡는지** 확인한다

## 8. 이번 범위에서 제외하는 것

| 제외 | 이유 |
|---|---|
| 시험 대비 문제·암기 카드 | 사장님이 고르지 않음 |
| OCR 프로그램 | 필요 없어졌다 — API가 페이지를 그림으로 본다 |
| 검색 인덱스 (임베딩) | 자료가 0개다. 목록 훑기로 충분하다 |
| 자동 실행 | 비용 |
| 폰에서 파일 넣기 | 텔레그램 파일 수신 배관이 필요하다. PC 폴더로 충분 |
| Files API 업로드 | 재질문이 싸지지만 원본이 앤트로픽 서버에 남는다 |
| 웹페이지 링크 요약 | 사장님이 고르지 않음. 외부 접속이 생기는 유일한 선택지였다 |

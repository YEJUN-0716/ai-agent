# 대시보드 리빌딩 — 설계

작성 2026-08-17 · 대상 `app.py` (Streamlit 1.59.2) · 승인 완료, 구현 계획 대기

## 1. 배경 — 왜 다시 만드나

사장님 진단 세 가지: **싸구려로 보인다 / 정보가 빽빽하다 / 폰에서 깨진다.**
코드를 보면 셋은 한 뿌리다. 모든 것이 한 페이지에 동시에 펼쳐져 있다.

- 최상단부터 헤더 → 티커 테이프 → 커맨드 바 → 시장 보드까지 네 블록을 지나야 판정이 나온다.
  사장님이 1순위로 꼽은 "오늘 뭐 사고 뭐 팔까"는 화면 어디에도 최상단에 없다.
- 우측 레일(`st.container(height=740)`)에 전 모듈 보고서가 동시에 경쟁한다.
  그 아래 분석 워크스페이스는 종목분석 전체가 항상 펼쳐져 있다.
- 본문 텍스트가 대부분 10.5~11px 인라인 스타일이고 본문색이 `#d1d4dc`(중간 회색)다.
  회색 배경 위 회색 글씨 + 작은 글씨 = "투박함"의 정체. 위계가 크기·여백이 아니라 색으로만 잡혀 있다.
- 인라인 `style=`이 화면 곳곳에 흩어져 있어 **뷰포트에 반응할 수 있는 지점이 없다.**
  `[2.5, 1]` 칼럼과 740px 고정 높이가 폰에서 그대로 유지된다.

색만 바꿔서는 셋 다 안 고쳐진다. IA(화면 구조)부터 손댄다.

## 2. 이번에 하는 것 / 안 하는 것

**한다**
- 최상위 화면 구조 재편 (한 페이지 → 레짐 스트립 + 5개 업무 화면)
- `[오늘]` 화면 신설 — 오늘의 액션 / 계좌 / 시장 / 모듈 상태
- 디자인 토큰(색·타이포·간격) 교체와 색 사용 규칙 확립
- 900px 단일 브레이크포인트 반응형
- `latest_signals.json` 산출물 신설 (홈이 즉시 읽을 수 있는 액션 목록)
- 새로 그리는 화면에 한해 공용 컴포넌트 헬퍼(`modules/ui.py`) 도입

**안 한다**
- 기존 27개 `render_*` 패널의 내부 재작성. 탭 안으로 **옮기기만** 한다.
- 분석 로직·팩터 엔진·백테스트·시그널 판정 로직 변경. 이번 작업은 표시 계층이다.
- 라이트 모드. 다크 단일 테마를 유지한다(2026-07 결정).
- 폰에서의 무거운 분석 실행. 폰은 확인용이다(§7).

## 3. 화면 구조 (IA)

```
[레짐 스트립]  SPY ▲0.4  QQQ ▲0.7  IWM ▼0.2  VIX 14.2  ·  레짐: 강세    (항상 노출, 한 줄)
──────────────────────────────────────────────────────────────────────
  오늘 │ 종목분석 │ 발굴·시그널 │ 검증 │ 운영                        (최상위 내비)
──────────────────────────────────────────────────────────────────────
```

기존 `ModuleGroup` 4그룹(`analyst`/`siggen`/`bt`/`ops`)을 그대로 화면으로 승격한다.
**데이터 구조는 안 건드리고 배치만 바뀐다.**

| 화면 | 내용 | 출처 (기존 함수) |
|---|---|---|
| **오늘** | 오늘의 액션 / 계좌 요약 / 시장 / 모듈 상태 | 신규 + `render_market_board` |
| **종목분석** | 커맨드 바 → 총괄 판정 → 분석 워크스페이스 → 트레이드 플랜 | `render_command_bar`, `render_verdict_hero`, `render_stock_analysis_panel`, `render_trade_plan_panel` |
| **발굴·시그널** | 팩터 랭킹 / 시스템 시그널 / 섹터 로테이션 / ML 신호 | `ModuleGroup('siggen')` 4개 패널 |
| **검증** | 팩터 백테스트 / 종목 백테스팅 / 고급 분석 / 워크포워드 | `ModuleGroup('bt')` 4개 패널 |
| **운영** | 실행 모드 / 시그널 파이프라인 / 리스크 가드레일 / 계좌 현황 | `ModuleGroup('ops')` 4개 패널 |

### 3.1 최상위 내비는 `st.tabs`가 아니라 `st.segmented_control`

`st.tabs`는 rerun 시 선택이 첫 탭으로 돌아간다. 이 앱은 분석이 끝나면
`st.rerun()`을 한 번 더 부른다(`app.py` 하단 `_analysis_done_flip`). 탭을 쓰면
분석할 때마다 화면이 [오늘]로 튄다.

→ `st.segmented_control`을 `st.session_state['nav']`에 묶어 쓴다. 선택이 세션에 남는다.
모듈 상태 점을 눌러 화면을 이동하는 동작(§3.2 ④)도 `session_state['nav']` 대입 한 줄로 된다.

기존 서브탭(`app.py:5616`의 포지션/차트/EV/리스크)은 `st.tabs` 그대로 둔다 — 그 안에서는 rerun이 안 걸린다.

### 3.2 `[오늘]` 화면 — 4블록

**① 오늘의 액션** (최상단, 이 화면의 유일한 주인공)

`latest_signals.json`(§4)에서 읽어 카드로 그린다.

- 정렬: `priority` HIGH → NORMAL, 같은 등급 안에서는 매도·비중축소를 매수보다 위에.
  (파는 결정이 사는 결정보다 시간에 민감하다)
- 노출: 기본 **상위 6개**, "더 보기"로 전체 펼침. `⚪ 관망`·`🟡 대기`는 기본 접힘.
- 카드 1장에 들어가는 것:
  `티커` · `액션`(매수/조건부 매수/매도/비중축소) · `현재가` · `제안 비중`·`수량` · `근거 한 줄` · `3개월 모멘텀`
- 카드에 **[플랜 보기]** 버튼. 누르면 그 종목만 `build_trade_plan`을 돌려
  진입 구간·손절·목표1·R:R·실행등급을 카드 안에 펼친다.
  → 6종목치를 미리 계산하지 않는다. 시세 다운로드가 화면 로딩을 잡아먹는다.
- 액션 색: 매수 초록 / 매도·축소 빨강 / 조건부·대기 앰버 / 관망 회색. 이모지 제거, 텍스트+색 점.
- 빈 상태: "아직 오늘 배치가 안 돌았습니다 — 마지막 배치 {시각}" + [발굴·시그널에서 직접 돌리기] 링크.

**② 내 계좌 한 줄** — 평가액 · 오늘 P&L · 포지션 수 · 현금 비중.
출처는 기존 `render_account_panel`이 쓰는 `equity_log.json` / `virtual_portfolio.json`.
숫자 4개만. 상세는 [운영] 화면에.

**③ 시장** — 기존 `render_market_board` 재사용(지수·변동성·금리·원자재 + 1개월 스파크라인).
상단 레짐 스트립과 중복되는 SPY/QQQ/VIX 타일은 스트립에 양보하고 보드에서 뺀다.

**④ 모듈 상태** — 전 모듈 보고서(`_groups`가 산출하는 전부)를 카드가 아니라 **상태 점 그리드**로 압축한다.
`모듈명 + 점(정상/주의/실패) + 한 줄 요약`. 누르면 `session_state['nav']`를 해당 화면으로 바꾸고
그 모듈을 펼친다. 기존 `render_report_rail`의 전장 동시 노출은 여기서 끝난다.

## 4. `latest_signals.json` — 오늘의 액션 데이터 계약

**문제**: 지금 액션 목록은 디스크에 없다. `signal_worker.py`가 메모리에서 만들어 통보만 하고,
`signal_log.json`에는 *매수* 시그널만 성적 추적용으로 기록한다.
홈에서 `generate_system_signals`를 다시 부르면 유니버스 전체 팩터 스캔이 걸린다 — 홈 화면에 못 쓴다.

**해결**: 워커가 배치 결과를 그대로 한 파일에 남기고, 홈은 읽기만 한다.

```json
{
  "generated_at": "2026-08-17T06:30:00+09:00",
  "universe": "S&P 500 전체 (500종목)",
  "capital": 10000,
  "rebal": {"next_rebal": "3일 후", "buy_count": 4, "sell_count": 2, "hold_count": 31},
  "actions": [
    {"ticker": "AAPL", "action": "🟢 매수", "weight": "4.0%", "price": "$333.74",
     "alloc": "$400", "qty": "1.20주", "reason": "팩터 61점 + 상승추세 (RSI 72)",
     "priority": "HIGH", "mom": "+8.3%"}
  ]
}
```

- `actions` 원소는 `signal_engine._make_action`이 이미 반환하는 dict를 **그대로** 쓴다. 변환 없음.
- 쓰는 쪽: `signal_worker.py` `main()` — `generate_system_signals` 호출 직후, 텔레그램 통보와 무관하게 기록.
  실패해도 워커 본 작업을 막지 않는다(try/except + 로그).
- 읽는 쪽: `[오늘]` 화면. 파일 없음/파싱 실패 → 빈 상태 카드(§3.2 ①).

**신선도 규칙 (필수)**: 어제 액션을 오늘 것처럼 보여주면 위험하다.
- `generated_at`을 카드 묶음 헤더에 항상 표시 — "2시간 전 배치".
- 마지막 미국장 개장일보다 오래됐으면 블록 상단에 앰버 배너: "N일 전 배치입니다 — 현재가와 다를 수 있습니다".
- 7일 초과면 액션 카드를 접고 배너만 남긴다.

## 5. 비주얼 — Modern Dark (슬레이트 터미널)

ui-ux-pro-max가 이 제품 유형에 "Modern Dark / fintech·trading dashboards"를 매칭했다.
딸려 온 글래스모피즘·블러·앰비언트 블롭은 **채택하지 않는다** — 숫자를 읽는 화면에서 블러는 장식이고 성능도 깎는다.

**색 사용 규칙 (이번 개편의 핵심 규칙)**

> **초록·빨강은 오직 방향(수익/손실·매수/매도)에만 쓴다.**

지금은 "정상 상태"에도 초록이 쓰인다. 그래서 초록을 봐도 수익인지 정상인지 알 수 없다.
- 방향 = 초록/빨강
- 상태(정상/주의/실패) = 회색 / 앰버 / 빨강 — 정상은 **색 없음**이 기본
- 선택·링크·강조 = 파랑
- 색만으로 뜻을 전하지 않는다. 상태 점에는 항상 텍스트 라벨을 붙인다.

### 5.2 타이포

플러그인은 Fira Sans + Fira Code를 권했지만, 현재 **Inter + JetBrains Mono**가 같은 성격이고 이미 로드돼 있다.
교체하지 않는다 — 폰트 바꾸는 건 순수 변경 비용이다. 대신 스케일을 강제한다.

- **11px는 대문자 모노 라벨 전용**(`ANALYSIS WORKSPACE` 같은 섹션 표제). 본문·수치에 11px 금지.
- 스케일: `11`(라벨) / `13`(보조) / `15`(본문) / `20`(섹션 제목) / `28`(핵심 수치)
- 굵기: 700(제목) / 600(강조·라벨) / 400(본문). 중간 굵기 남발 금지.
- **모든 숫자에 `font-variant-numeric: tabular-nums`.** 자릿수가 흔들리는 게 아마추어 티의 절반이다.
- 이모지 아이콘(📈📡🔬⚙️🎯) 제거. 내비는 한글 텍스트, 상태는 색 점 + 라벨.

### 5.3 간격

`--space-1:4 / 2:8 / 3:12 / 4:16 / 6:24 / 8:32`. 블록 사이 24, 섹션 사이 32, 카드 안쪽 16.
인라인 `margin:16px 0 8px 0` 같은 임의값을 새 화면에서는 쓰지 않는다.

### 5.4 모션

150~200ms, `ease-out`. hover/선택 상태 전환에만. 장식 애니메이션 없음.
`prefers-reduced-motion: reduce`에서 전부 끈다.

## 7. 반응형

브레이크포인트는 **900px 하나**. 사장님은 PC 위주, 폰은 확인용이다.

- `< 900px`: 모든 `st.columns` 세로 적층, `height=740` 고정 컨테이너 해제(`height=None`),
  표는 `overflow-x:auto` 래퍼, 카드 그리드 1열, 최상위 내비는 가로 스크롤 허용.
- 폰 목표는 **[오늘] 화면만 제대로** — 레짐·오늘의 액션·계좌를 읽을 수 있으면 합격.
  나머지 화면은 "깨지지 않는" 수준(가로 스크롤 없음, 글자 안 잘림)까지.
- `.block-container`의 `max-width:1600px`은 유지, 좌우 패딩만 좁은 화면에서 `2rem → 1rem`.

**미검증 — 구현 1단계에서 실측한다**: Streamlit 1.59에서 `st.columns`가 375px에서 실제로
어떻게 접히는지 확인 안 했다. 자동으로 안 접히면 `[data-testid="stHorizontalBlock"]`에
`flex-direction:column`을 미디어쿼리로 강제한다.

## 8. 알려진 제약 (2026-07 개편에서 실측된 것)

1. Streamlit이 버튼 `background`/`border`를 `!important`로 잠근다.
   커스텀 상태색은 그 두 속성으로 못 칠한다 — `box-shadow: inset`(좌측 바·배경 틴트)은 통한다.
   `display`/`text-align`/`font`/`white-space`는 통한다.
2. `st.button(key=...)`은 `st-key-<key>` 클래스가 된다.
   **키에 한글이나 `+`가 들어가면 CSS 셀렉터가 깨진다** — 순번 기반 키를 쓴다.
3. `st.columns`의 화면상 위치는 `st.columns()` 호출 시점에 정해지고, 채우는 순서와 무관하다.
   단 `st.button()` 평가 순서는 코드 순서를 따르므로, 클릭 반영이 한 박자 늦지 않으려면
   **내비를 먼저 그리고 본문을 나중에 그린다.**

# 가상 브로커를 팩터 엔진에서 트레이드 플랜으로 교체 — 설계

- 날짜: 2026-08-10
- 지시: "가상 브로커를 팩터 엔진 → 트레이드 플랜으로 바꾼다"
- 대상: `paper_trade_runner_toss.py`, `modules/virtual_broker.py`
- 근거 실측: `docs/measurements/2026-08-09-trade-plan-oos.md`(6.4년·15,275셋업),
  `docs/measurements/2026-08-10-trade-plan-cost-sensitivity.md`(13,336건)

## 1. 왜

가상 장부(2026-07-31 가동)는 팩터 점수 상위 종목을 다음 거래일 시가에 사고,
트레일링 스톱 10%·팩터 매도 시그널로 팔았다. 그 사이 트레이드 플랜
(`modules/trade_plan.py`)이 진입구간·손절·목표·실행등급까지 갖추고 6.4년
OOS 로 채점까지 끝났다. **측정된 규칙은 트레이드 플랜 쪽인데 돈(가상)은 측정이
덜 된 규칙으로 돌고 있었다.** 이 설계는 그 둘을 일치시킨다.

실측 기준선 (롱, 6.4년 OOS):

| | 값 |
|---|---|
| 셋업 | 12,037 |
| 체결 | 7,675 (**64%** — 36%는 진입구간 미도달로 폐기) |
| 승률(결판난 것) | 38% |
| 기대값 | **+0.66R** |

등급별 순 기대값(편도 20bp 반영): 롱 A +0.56R, B +0.43R, C +0.37R, D +0.22R.
총 R 은 등급 간 평평하고 **다른 것은 비용 내성뿐**이다. 그래서 A·B 만 실행한다
(`trade_plan.ACTIONABLE_GRADES`). 숏은 어느 등급이든 롱의 1/3 이라 실행하지
않는다(`ACTIONABLE_DIRECTIONS = ("long",)`) — 계산·기록은 그대로 하고 관찰만.

## 2. 결정 사항 (2026-08-10 보스 승인)

| 갈림길 | 결정 | 이유 |
|---|---|---|
| 팩터 엔진 | **완전 교체.** 러너에서 팩터 점수를 아예 안 씀 | 지시대로 "바꾸는" 것. 앱·성적표의 팩터 경로는 그대로 남는다 |
| 진입 | **진입구간 지정가 대기**(최대 20거래일, 미체결이면 폐기) | 백테스트가 채점한 것이 이 방식이다. 시가 시장가로 사면 손절폭·R:R 이 계획과 달라져 +0.66R 이 이 장부에 적용되지 않는다 |
| 청산 | **손절 / T1 선착.** 40거래일 미결이면 청산 | 백테스트 `_simulate_outcome` 과 동일 규칙. T2 분할·트레일링 병용은 측정된 적 없는 새 규칙이라 배제 |
| 사이징 | **위험 기준.** 1R = 자본의 0.5%, 종목당 상한 자본의 15% | 이 시스템의 손절은 1.3~3% 로 촘촘해서, 위험을 1% 로 잡으면 한 종목이 자본의 40% 가 된다. 0.5%+15% 상한이면 동시 5~7종목 |
| 기존 보유 | **트레일링 10% 로 마무리.** 새 매수는 플랜만 | KHC·GM 등은 라인 없이 산 것이라 사후에 라인을 붙이면 R 이 거짓이 된다. 규칙이 섞이지 않게 기존분만 옛 규칙으로 소감시킨다 |

## 3. 구조

### 3.1 브로커: 주문 종류를 늘린다 (작업의 8할)

현재 `virtual_broker.settle_pending` 은 **"주문일 다음 거래일 시가에 무조건
체결"** 한 종류만 안다. 여기에 두 개를 더한다. 기존 시장가 경로는 **그대로 둔다**
— 비서(챗봇)의 수동 매수가 `place_notional_buy` 를 쓴다.

**(a) 지정가 진입 주문**

대기 주문에 필드 추가:

```
kind          "limit_entry"          (없으면 기존 시장가 동작 — 하위호환)
limit_price   진입구간 상단(롱)
plan          {entry_ref, stop, target, rr, grade, risk_pct}
expire_after  20 (거래일)
```

정산: 주문일 **다음 일봉부터 순서대로** 훑어

- `저가 <= limit_price` 인 첫 봉에서 체결
- 체결가 = `min(그 봉의 시가, limit_price)` — 갭하락으로 구간을 뛰어넘고 열리면
  실제로 받는 값은 시가다. 이걸 `limit_price` 로 고정하면 장부가 현실보다
  좋아진다
- 20거래일 안에 안 닿으면 주문 폐기(현금 예약 해제) + `nofill` 기록

**(b) 라인 청산**

포지션에 플랜을 저장한다: `positions[sym]["plan"] = {entry_fill, stop, target,
rr, grade, risk_pct, hold_expire}`. 같은 일봉 훑기에서

- `저가 <= stop` → 손절, 체결가 = `min(시가, stop)`
- `고가 >= target` → 익절, 체결가 = `max(시가, target)`
- **한 봉에 둘 다 → 손절 우선** (백테스트와 동일. 일봉만으로는 순서를 모르므로
  보수적으로)
- 40거래일 경과 → 그 봉 시가로 청산(`timeout`)

**부수 효과(중요):** 판정이 러너 실행 순간의 종가가 아니라 **일봉 되짚기**로
일어나므로, 주말·공휴일·러너 실패로 며칠 빠져도 결과가 안 바뀐다. 현재
`check_trailing_stops` 는 러너가 도는 순간의 종가만 봐서 그 사이의 손절 이탈을
놓친다. 이 설계에는 그 구멍이 없다.

**정산 순서:** 한 번의 `settle_pending` 안에서 (1) 보유 포지션 청산 판정 →
(2) 지정가 진입 체결. 청산이 먼저여야 같은 날 현금·자리가 정확히 계산된다.

### 3.2 러너: 후보 선정을 갈아낸다

```
1. settle_pending  (청산 → 지정가 체결 → 만료 폐기)
2. 체결·청산분을 성적표에 기록
3. 레짐 감지 → 보유 상한 조정        (유지)
4. 낙폭 컷 / 킬스위치                 (유지)
5. 기존 보유분 트레일링 스톱 점검     (유지, 기존 5종목 대상)
6. 유니버스 → 일봉 패널 → build_trade_plan 전 종목
7. actionable 만 남김 → A등급 우선, 같은 등급이면 진입가 근접 순
8. 섹터 한도·자리·현금 확인 → 위험 기준 수량 계산 → 지정가 주문 예약
9. 자산 로그 · 텔레그램 보고
```

**빠지는 것**: `calc_factor_scores`, `generate_signals`, `BUY_SCORE_MIN`,
`TOP_N` 기반 선택, 변동성 사이징, 상관관계 페널티 사이징, `_calc_ict_batch`
(플랜이 내부에서 `calc_ict_adjustment` 를 이미 부른다), 팩터 매도 경로.

**남는 것**: 레짐, 낙폭 컷, 킬스위치, 섹터 한도, 자산 로그, 성적표, 텔레그램.

**순위 기준**: A등급 먼저, 같은 등급 안에서는 현재가에서 진입가까지의 거리가
가까운 순. 등급 안에서는 기대값이 구별되지 않는다고 이미 측정됐으므로
(`_confidence` 주석의 부트스트랩 구간이 0 을 포함), 안 측정된 순위 기준을 새로
만들지 않고 **체결 확률이 높은 쪽**을 택한다.

**사이징**:

```
risk_krw  = equity_krw * 0.005
qty       = floor(risk_krw / ((entry_ref - stop) * fx))
notional  = min(qty * entry_ref * fx, equity_krw * 0.15)
→ 1주도 못 사면 스킵 (소수점 거래 불가)
```

자리 계산은 **보유 + 대기 중인 지정가 주문**을 함께 센다. 기존
`order_accepted()` 가 "체결 확인"과 "자리 차지"를 분리해 둔 것과 같은 이유다 —
20거래일 대기하는 주문이 자리를 안 차지하면 상한이 통째로 꺼진다.

### 3.3 기록

체결·청산 기록에 남기는 값:

| 필드 | 시점 | 뜻 |
|---|---|---|
| `grade`, `risk_pct`, `rr` | 주문 | 실행등급·위험폭·계획 R:R |
| `entry_fill`, `stop`, `target` | 체결 | 실제 체결가와 라인 |
| `outcome` | 청산 | `win` / `loss` / `timeout` / `nofill` |
| `r_realized` | 청산 | (청산가 − 진입가) ÷ (진입가 − 손절가) |

`r_realized` 가 이 작업의 진짜 산출물이다. 이게 있으면 장부 성적을 백테스트의
**+0.66R 과 같은 단위로 직접 비교**할 수 있다. 지금 장부는 %수익률만 남아 그게
안 된다.

`signal_log` 의 `score` 는 **빈칸으로 둔다.** 팩터 점수가 없으니
`signal_scorecard.by_score_bucket` 의 점수 구간별 표는 새 매수부터 안 자란다.
ICT 점수를 그 칸에 넣지 않는다 — 한 칸이 두 질문에 답하기 시작하는 지점이고,
그러면 나중에 어느 쪽을 고쳐야 할지 알 수 없다. 등급별 표는 별건.

## 4. 테스트

`_simulate_outcome` 이 이미 순수 함수로 테스트돼 있으므로, 새 코드도 같은
모양으로 순수 함수를 분리해 결정적으로 테스트한다. 네트워크 없음.

- 지정가 체결: 구간에 닿는 날 체결 / 20거래일 미도달 폐기 / 갭하락 시 체결가가
  시가
- 라인 청산: 손절 / 목표 / **한 봉에 둘 다 → 손절** / 40거래일 timeout /
  갭 청산가
- `r_realized` 계산 (손절 −1.0 근방, 목표 +rr 근방)
- 사이징: 위험 0.5% 환산, 15% 상한 발동, 1주 미달 스킵
- 후보 순위: A 가 B 앞, 같은 등급이면 진입가 근접 순
- 하위호환: `kind` 없는 기존 대기 주문이 예전대로 시가 체결

## 5. 안 되는 것 / 위험

- **장부 R 은 백테스트보다 약간 나쁠 것이다.** 백테스트는 진입가를 구간
  기준값으로 가정했고, 장부는 실제 체결가로 R 을 계산한다. 갭 체결이 그 차이다.
- **수수료·슬리피지는 여전히 안 잰다.** 등급이 비용 내성을 보장할 뿐이다
  (A: 손익분기 편도 88.8bp, B: 53.3bp).
- **표본 쌓이는 속도가 느려진다.** 10건 걸어 6~7건 체결이고, 하루에 A·B 롱
  셋업이 몇 개 나오는지는 실제로 돌려봐야 안다. 첫 주는 주문이 0건인 날도
  있을 수 있다.
- 기존 팩터 보유 5종목이 소감될 때까지 장부에는 **두 규칙이 섞여 있다.**
  성과를 볼 때 `plan` 이 붙은 트레이드만 따로 봐야 한다.
- 유니버스 전 종목 일봉이 필요하다. `price_panel.load_panel` 이 이미 하는 일이라
  새 네트워크 부담은 팩터 스코어를 빼는 만큼 오히려 줄어든다.

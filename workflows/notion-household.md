# 노션 살림 대시보드 (가계부 + 일정)

## 목표

노션 안에 페이지 1개 + 데이터베이스 2개. 달력으로 보고 노션 앱에서 직접 적는다.
가계부는 **월별 총지출과 분류별 합계**가 차트로 나온다.

화면도 노션, 입력도 노션이다. 이 저장소의 코드는 관여하지 않는다.

## 만든 것 (2026-09-01 가동)

상위 페이지 **살림** — https://app.notion.com/p/3ce8362ea024811b8589cf9f2b54bc0d
개인 페이지로 만들었다. 팀스페이스로 옮기려면 사장님이 노션에서 옮기면 된다.

페이지 본문에 두 달력이 인라인으로 박혀 있고, 각 데이터베이스는 자기 탭을 갖는다.

### ① 가계부

| 속성 | 타입 |
|---|---|
| 항목 | 제목 |
| 날짜 | 날짜 |
| 금액 | 숫자 (원화 `won` 서식) |
| 분류 | 선택 — 식비/교통/주거/생활/문화/의료/기타 |
| 구분 | 선택 — 지출/수입 |
| 월 | 수식 `formatDate(prop("날짜"), "YYYY-MM")` |
| 메모 | 텍스트 |

뷰 9개:

| 뷰 | 종류 | 하는 일 |
|---|---|---|
| 전체 | 표 | 날짜 내림차순. 적고 훑는 곳 |
| 달력 | 캘린더 | 언제 썼나 |
| 9월 / 10월 / 11월 / 12월 | 차트(세로막대) | 그 달 지출·수입 합계 (구분별 막대 2개) |
| 지출 추이 | 차트(선) | 날짜별 지출 흐름 |
| 분류별 | 차트(도넛) | 분류별 지출 비중 |
| 총지출 | 차트(숫자) | 전체 기간 지출 합계 |

**월별 합계를 달마다 뷰 하나로 만든 이유:** 차트의 날짜 그룹 단위를 API로 못
정한다(항상 `day`). 「월」 수식으로 그룹하는 것도 안 된다. 그래서 월별 합계는
날짜 범위를 못 박은 차트로 낸다. 지난 달 값은 확정이라 안 썩고, 이번 달은 살아서
갱신된다. **대신 자동으로 안 늘어난다 — 해가 바뀌면 뷰를 더 만들어야 한다.**

각 월 뷰는 `구분`으로 그룹한 세로막대라 **지출과 수입이 막대 2개로 같이 나온다.**
지출만 보려고 `구분 = 지출` 필터를 걸면 수입 막대가 사라지므로 걸지 않는다.

### ② 할일

제목 / 날짜(범위 허용) / 상태(할일·진행·완료) / 우선순위(높음·보통·낮음) / 메모

| 뷰 | 종류 | 하는 일 |
|---|---|---|
| 달력 | 캘린더 | 일정 |
| 남은 일 | 표 | 완료 아닌 것만, 날짜·우선순위순 |

## 사장님이 눌러야 하는 것

없다. 처음엔 차트 그룹 단위를 손으로 바꾸시라고 안내했는데, 사장님이 그 설정을
못 찾으셔서 월별 카드 방식으로 갈아엎었다. **클릭을 요구하는 설계는 실패한 설계였다.**

예시 줄 3개(가계부 2, 할일 1)를 넣어 도는 걸 확인했다. 확인하셨으면 지우면 된다.

## 이번에 실제로 부딪힌 벽

앞서 이 문서에 적었던 두 가지는 **틀렸다.** 실측으로 뒤집혔다:

- ~~노션 API는 뷰를 못 만든다~~ → claude.ai 노션 커넥터에는 `create-view`가 있다.
  달력·차트·필터·정렬까지 만든다. 손으로 만들 필요 없었다.
- ~~「월」 수식 속성이 이 설계의 핵심이다~~ → **수식 속성으로는 GROUP BY가 안 된다.**
  차트도 표도 안 된다. 지금 「월」은 표에서 읽히는 라벨일 뿐, 집계를 만들지 않는다.

대신 진짜 벽은 여기였다:

- **뷰 DSL에 상대 날짜가 없다.** "이번 달", "오늘" 같은 필터를 못 쓴다. ISO 날짜만
  된다. 그래서 "이번 달"을 뜻하는 뷰는 만들 수 없고, 달마다 범위를 못 박은 카드를
  하나씩 만든다. 지난 달은 값이 확정이라 안 썩지만, **새 달은 자동으로 안 생긴다.**
- **차트의 날짜 그룹 단위는 항상 `day`로 만들어진다.** DSL에 단위 지시자가 없다.
  `GROUP BY "날짜" BY month`·`MONTH` 둘 다 문법 오류로 거부된다. UI에서만 바뀐다.
  → 월별 합계는 그룹이 아니라 **날짜 범위를 못 박은 `number` 차트**로 낸다.
- **`create-view`는 실패해도 성공처럼 답한다.** 설정이 거부되면 오류 대신
  `Created view "이름" (chart)` 한 줄만 오고 `view://` URL이 빠진다. 뷰는 안 생긴다.
  → **응답에 `view://`가 없으면 실패다.** 만든 뒤 `fetch`로 뷰 목록을 확인할 것.
- **뷰 삭제 도구가 없다.** 잘못 만든 뷰는 `update-view`로 고쳐 쓰거나 사람이 지운다.
  그래서 시행착오는 뷰를 늘린다 — 설정을 먼저 검증하고 만드는 편이 싸다.

## 일정 넣기 (사장님이 말로 던지면 내가 넣는다)

`할일` 데이터소스에 `create-pages`로 꽂는다. 시간이 있는 일정은
`date:날짜:start`/`end`를 ISO datetime으로 주고 `date:날짜:is_datetime`을 1로 둔다.
한 번에 100개까지 들어간다.

**수업처럼 반복되는 일정은 「상태」를 비워둔다.** 노션 API에 반복 일정이 없어서
주차별로 낱개 행이 된다(한 학기 = 16주). 「상태」를 채우면 이것들이 `남은 일`
뷰를 덮으므로, 그 뷰 필터를 `상태 IN (할일, 진행)`으로 좁혀뒀다. 빈 상태는
안 걸린다.

**요일과 시작일을 손으로 세지 말 것.** "9월 1일부터 월요일마다"에서 9월 1일이
월요일이 아닐 수 있다(2026-09-01은 화요일이었다). 파이썬으로 날짜를 뽑고 시작
요일을 사장님께 알린다.

**한글을 유니코드 이스케이프로 쓰지 말 것.** `전공실험2`를 `픘2`로 잘못 써서
`전공실픘2` 16개가 들어갔다. 고치는 데 update-page 16번이 들었다. 한글은 그대로
쓰고, 생성 응답에 찍힌 제목을 눈으로 확인한다.

# 노션 살림 대시보드 (가계부 + 일정)

## 목표

노션 안에 페이지 1개 + 데이터베이스 2개. 달력으로 보고 노션 앱에서 직접 적는다.
가계부는 **월별 총지출과 분류별 합계**가 차트로 나온다.

화면도 노션, 입력도 노션이다. 이 저장소의 코드는 관여하지 않는다.

## 만든 것 (2026-09-01 가동)

상위 페이지 **살림** — https://app.notion.com/p/3ce8362ea024811b8589cf9f2b54bc0d
개인 페이지로 만들었다. 팀스페이스로 옮기려면 사장님이 노션에서 옮기면 된다.

페이지 본문에 두 달력이 인라인으로 박혀 있고, 각 데이터베이스는 자기 탭을 갖는다.

### ① 가계부

| 속성 | 타입 |
|---|---|
| 항목 | 제목 |
| 날짜 | 날짜 |
| 금액 | 숫자 (원화 `won` 서식) |
| 분류 | 선택 — 식비/교통/주거/생활/문화/의료/기타 |
| 구분 | 선택 — 지출/수입 |
| 월 | 수식 `formatDate(prop("날짜"), "YYYY-MM")` |
| 메모 | 텍스트 |

뷰 5개:

| 뷰 | 종류 | 하는 일 |
|---|---|---|
| 전체 | 표 | 날짜 내림차순. 적고 훑는 곳 |
| 달력 | 캘린더 | 언제 썼나 |
| 월별 지출 | 차트(세로막대) | 날짜 그룹 + 금액 합계, 지출만 |
| 분류별 | 차트(도넛) | 분류별 지출 비중 |
| 총지출 | 차트(숫자) | 전체 기간 지출 합계 |

### ② 할일

제목 / 날짜(범위 허용) / 상태(할일·진행·완료) / 우선순위(높음·보통·낮음) / 메모

| 뷰 | 종류 | 하는 일 |
|---|---|---|
| 달력 | 캘린더 | 일정 |
| 남은 일 | 표 | 완료 아닌 것만, 날짜·우선순위순 |

## 사장님이 한 번만 눌러야 하는 것

**`월별 지출` 차트의 그룹화 단위를 '일' → '월' 로 바꾼다.** 차트 우상단 ⚙에 있다.
API로는 단위를 못 정한다(아래 참조). 차트 캡션에도 같은 안내를 적어뒀다.

예시 줄 3개(가계부 2, 할일 1)를 넣어 도는 걸 확인했다. 확인하셨으면 지우면 된다.

## 이번에 실제로 부딪힌 벽

앞서 이 문서에 적었던 두 가지는 **틀렸다.** 실측으로 뒤집혔다:

- ~~노션 API는 뷰를 못 만든다~~ → claude.ai 노션 커넥터에는 `create-view`가 있다.
  달력·차트·필터·정렬까지 만든다. 손으로 만들 필요 없었다.
- ~~「월」 수식 속성이 이 설계의 핵심이다~~ → **수식 속성으로는 GROUP BY가 안 된다.**
  차트도 표도 안 된다. 지금 「월」은 표에서 읽히는 라벨일 뿐, 집계를 만들지 않는다.

대신 진짜 벽은 여기였다:

- **뷰 DSL에 상대 날짜가 없다.** "이번 달", "오늘" 같은 필터를 못 쓴다. ISO 날짜만
  된다. 날짜를 박아두면 다음 달에 썩으므로, 월별 집계는 필터가 아니라 **날짜 그룹
  차트**로 푼다.
- **차트의 날짜 그룹 단위는 항상 `day`로 만들어진다.** DSL에 단위 지시자가 없다.
  월 단위는 사람이 한 번 클릭한다.
- **`create-view`는 실패해도 성공처럼 답한다.** 설정이 거부되면 오류 대신
  `Created view "이름" (chart)` 한 줄만 오고 `view://` URL이 빠진다. 뷰는 안 생긴다.
  → **응답에 `view://`가 없으면 실패다.** 만든 뒤 `fetch`로 뷰 목록을 확인할 것.
- **뷰 삭제 도구가 없다.** 잘못 만든 뷰는 `update-view`로 고쳐 쓰거나 사람이 지운다.
  그래서 시행착오는 뷰를 늘린다 — 설정을 먼저 검증하고 만드는 편이 싸다.

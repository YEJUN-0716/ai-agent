# AI 업무 비서

## 목표

텔레그램(휴대폰)과 PC 브라우저에서 같은 비서에게 말을 건다.
비서는 주식 분석 결과를 읽고, 관심종목·메모를 기록하고, 가상 매매를 제안한다.

## 준비

1. `.env.example`을 `.env`로 복사하고 다음을 채운다.

   | 항목 | 무엇 |
   |---|---|
   | `ANTHROPIC_API_KEY` | Claude API 키 |
   | `STOCK_ANALYZER_PATH` | stock-analyzer 폴더 경로 |
   | `TELEGRAM_BOT_TOKEN` | @BotFather에게 받은 봇 토큰 (선택) |
   | `TELEGRAM_ALLOWED_CHAT_IDS` | 내 chat_id. 여기 없는 사람은 봇이 무시한다 |

   메신저 창구는 텔레그램·디스코드 둘 다 선택이다. **토큰을 비우면 그 창구를
   열지 않는다** — 텔레그램을 안 쓰기로 했으면 `TELEGRAM_BOT_TOKEN`을 비우고
   서버를 다시 띄우면 된다. 코드를 지울 필요는 없다. 둘 다 비우면 웹 채팅만
   돌고, 시작 로그가 그 사실을 알린다.

   내 chat_id 확인법: 봇에게 아무 말이나 보낸 뒤
   `https://api.telegram.org/bot<토큰>/getUpdates` 를 브라우저로 연다.

   디스코드도 쓰려면 아래 둘을 더 채운다. 비워두면 디스코드 창구는 안 열린다.

   | 항목 | 무엇 |
   |---|---|
   | `DISCORD_BOT_TOKEN` | Discord 개발자 포털 → Bot → Reset Token |
   | `DISCORD_ALLOWED_USER_IDS` | 내 user_id. 여기 없는 사람은 봇이 무시한다 |

   디스코드 봇 만드는 순서 (한 번만 하면 된다):
   1. https://discord.com/developers/applications → New Application
   2. 왼쪽 Bot 탭 → **MESSAGE CONTENT INTENT를 켠다.** 이걸 안 켜면 봇이
      접속은 되는데 메시지 내용이 빈 채로 와서 아무 답도 못 한다.
   3. 같은 화면 Reset Token → 나온 토큰을 `.env`에 넣는다
   4. OAuth2 → URL Generator → scopes에 `bot`, 권한은 Send Messages만 체크 →
      나온 주소를 열어 내 서버에 초대한다
   5. 내 user_id 확인: 디스코드 설정 → 고급 → 개발자 모드 켜기 → 내 이름
      우클릭 → "사용자 ID 복사"

2. `pip install -r requirements.txt`

## 실행

```
python server.py
```

- 웹 채팅: http://127.0.0.1:8765
- 텔레그램: 봇에게 그냥 말을 건다
- 디스코드: 봇에게 DM을 보내거나, 봇이 있는 채널에서 말을 건다

셋은 같은 대화 기록을 본다. 폰에서 물어본 걸 PC에서 이어 물을 수 있다.

## 쓰는 법

평소처럼 물어보면 된다.

- "가상 브로커 지금 얼마야?"
- "최근 시그널 5개 보여줘"
- "엔비디아 관심종목에 넣어줘, 실적 발표 대기중이라고"
- "애플에 대해 메모 남겨줘: 가이던스 확인 후 재검토"
- "지난주에 내가 뭘 바꿨지?"

## 학업 자료

바탕화면 **`자료넣는곳`** 폴더에 PDF를 끌어다 놓고, 비서에게 말한다.

- "새로 넣은 자료 정리해줘" → 읽고 요약해 옵시디언 `학업` 폴더에 노트를 만든다
- "정리해둔 자료 목록 보여줘"
- "그 논문 3장 예시가 뭐였지?" → 요약에 없으면 원본을 다시 펼쳐 답한다

PDF를 통째로 넘기므로 **그림·수식·표까지 읽는다.** 스캔본도 된다.

**정리에는 돈이 든다** (100쪽에 2,000~3,000원). 그래서 폴더에 넣어두기만 하면
아무 일도 일어나지 않는다. 말해야 움직인다. 그 뒤의 질문은 요약 노트만 읽으므로
훨씬 싸다.

원본 PDF는 `자료넣는곳/처리완료`로 옮겨질 뿐 **지워지지 않는다.** 쌓인 게
거슬리면 직접 지우면 된다.

## 옵시디언 노트 검색

볼트 안의 노트를 비서가 뒤져서 답한다. **공짜다** — 이 PC의 파일을 읽을 뿐
API를 쓰지 않는다.

- "손절 규칙 어디에 적어놨더라?"
- "트랜스포머 노트에서 어텐션 부분 찾아줘"
- "관심종목 관련해서 내가 적어둔 거 있어?"

찾는 범위는 **볼트 전체** — 직접 쓴 노트, `학업` 요약, `Agent Memory`,
`Stock Analyzer` 자동 노트까지. 옵시디언 설정 폴더(`.obsidian`)와 휴지통은 뺀다.
조사가 붙어도 찾는다("어텐션"으로 "어텐션은"이 걸린다).

질문 순서도 이 검색이 먼저다: **볼트 검색(공짜) → 노트 열기(공짜) → 그래도
없으면 원본 PDF(유료)**. 볼트에 답이 있으면 돈이 안 든다.

못 찾으면 "볼트에 없다"고 답한다. 없는 내용을 지어내지 않는다.

색인을 만들지 않고 매번 전부 훑는다. 노트 수백 개까지는 눈 깜짝할 새다.
느려지면 그때 `tools/obsidian_search.py`에 색인을 붙인다.

## 옵시디언 노트 쓰기 — `비서` 폴더 안에서만

- "오늘 통화 내용 노트로 만들어줘" → 볼트 `비서` 폴더에 새 노트가 생긴다
- "그 노트에 이것도 추가해줘" → 노트 맨 뒤에 날짜 소제목과 함께 붙는다

**할 수 있는 건 이 둘뿐이다.** 세 가지가 구조적으로 막혀 있다:

1. **`비서` 폴더 밖에는 못 쓴다.** 직접 쓴 노트도, `학업` 요약도 안전하다.
2. **덮어쓰기가 없다.** 같은 이름의 노트를 만들려 하면 거절된다.
3. **지우거나 고치는 함수 자체가 없다.** 덧붙이기만 된다.

그래서 비서가 판단을 틀려도 **잃는 글자가 없다.** 최악이 "쓸데없는 노트가
하나 생긴다"이고, 그건 사장님이 지우면 끝이다.

무엇을 언제 썼는지는 **"최근에 뭐 바꿨어?"**로 확인한다 (감사 기록에
`note_create` / `note_append`로 남는다). 승인 절차를 안 넣은 이유가 이것이다 —
돈이 안 움직이고, 되돌릴 것도 없고, 기록은 남는다.

## 매매는 두 단계다

비서는 매매를 **제안만** 한다. 실행 권한이 없다.

1. "애플 100만원어치 사는 걸로 해줘" → 비서가 제안하고 승인 번호를 준다
2. `/승인 <번호>` → 그때 실제로 가상 브로커에 주문이 들어간다

| 명령 | 하는 일 |
|---|---|
| `/승인` | 대기 중인 제안 목록 보기 |
| `/승인 <번호>` | 승인해서 주문 넣기 |
| `/거절 <번호>` | 제안 버리기 |

채팅으로 "승인해서 바로 사줘"라고 해도 나가지 않는다. 승인 명령만이 주문을 낸다.
**실제 돈으로 하는 주문 기능은 이 시스템에 없다.**

## 무슨 일이 있었는지 확인하기

관심종목 변경·메모·매매 제안과 승인은 전부 `data/assistant/audit.log`에 남는다.
비서에게 "지난주에 뭘 바꿨지?"라고 물으면 읽어서 알려준다.

파일이 망가지는 일이 생기면 비서가 원본을 `.corrupt` 이름으로 보관하고
기록을 남긴다. 조용히 덮어쓰지 않는다.

## 도구를 하나 더 붙이려면

1. `tools/`에 파이썬 파일을 만든다. 함수는 `Settings`를 첫 인자로 받는다.
2. `tests/`에 테스트를 쓴다. 진짜 데이터에 의존하지 말고 `tmp_path`를 쓴다.
3. `assistant/brain.py`의 `_build_tools()`에 `@beta_tool` 함수를 더한다.
   도크스트링이 곧 비서가 읽는 설명서다 — 언제 쓰는 도구인지 명확히 쓴다.
4. **되돌릴 수 없는 행동이라면 실행 함수를 도구 목록에 넣지 않는다.**
   `tools/virtual_trade.py`처럼 제안과 승인을 분리하고, 승인은 창구가 부른다.

테스트를 쓸 때 한 가지: 항목이 하나뿐인 결과로 순서를 검증하면 정렬 코드를
지워도 통과한다. 이 프로젝트에서 실제로 겪은 일이다. 항목을 둘 이상 두고
정확한 순서를 확인한다.

### stock-analyzer를 건드릴 때 (읽고 시작할 것)

비서와 stock-analyzer는 **함수 호출로만** 이어져 있다. 타입도 스키마도 없어서,
한쪽을 고치면 다른 쪽이 조용히 깨진다. 2026-07-30 하루에 같은 자리에서 반대
방향 실수가 두 번 나왔다.

| 실수 | 결과 |
|---|---|
| 달러를 원화로 오인 | 623달러 → 623원. 1주 값보다 작아 매수 0건 |
| 원화를 달러로 오인 | 50만원 → 7억원. 현금 부족으로 조용히 폐기 |

두 번째는 첫 번째를 고치다가 만들었다. 러너 쪽만 확인하고 비서 쪽을 안 봤다.
그때 테스트 106개가 전부 통과했다 — 전부 가짜 브로커를 주입해서 진짜 계약을
아무도 지나가지 않았기 때문이다.

그래서:

1. `stock-analyzer`의 함수를 고치면 **비서 쪽 호출부도 같이 연다.** 반대도 같다.
2. 금액을 다루면 **단위를 먼저 확인한다.** `notional_amount`처럼 단위가 이름에
   없는 인자가 이 시스템의 상습 지뢰다. `place_notional_buy`는 달러를 받는다. 원화를 넘길 땐 `krw_per_usd()`로 나눈다.
3. `tests/test_broker_seam.py`가 진짜 `virtual_broker`를 부르는 **유일한** 파일이다.
   계약이 바뀌면 여기부터 고친다.
4. 고친 뒤 **코드를 일부러 되돌려 테스트가 실제로 잡는지 확인한다.**
   안 잡으면 그 테스트는 없는 것과 같다.

한글 콘솔(cp949)은 `—` 한 글자에 터진다. 브로커가 찍는 글자가 거래를 망치지
않도록 `_run_broker()`가 출력을 가로채고, `server.py`는 시작할 때 콘솔을
UTF-8로 맞춘다. 새 진입점을 만들면 같은 처리를 빠뜨리지 말 것.

## 고장났을 때

| 증상 | 확인할 것 |
|---|---|
| `설정 오류: ...` | `.env`의 해당 항목 |
| 웹을 폰에서 열고 싶다 | 안 된다. 웹은 이 PC 전용이고, `ASSISTANT_WEB_HOST`에 외부 주소를 넣으면 시작할 때 막는다. 폰에서는 텔레그램을 쓴다 |
| 답 끝에 "…여기서 멈췄습니다" | 비서가 도구를 너무 많이 쓰다 상한에 걸렸다. 질문을 좁혀서 다시 묻는다 |
| 텔레그램이 답을 안 함 | `TELEGRAM_ALLOWED_CHAT_IDS`에 내 chat_id가 있는지 |
| 디스코드가 답을 안 함 | ① 개발자 포털에서 MESSAGE CONTENT INTENT가 켜져 있는지 (꺼져 있으면 내용이 빈 채로 온다) ② `DISCORD_ALLOWED_USER_IDS`에 내 user_id가 있는지 |
| 디스코드 창구가 아예 안 뜸 | `DISCORD_BOT_TOKEN`이 비어 있으면 일부러 안 연다. 시작 로그에 "디스코드 접속" 줄이 있는지 본다 |
| "주식 데이터를 읽지 못했습니다" | `STOCK_ANALYZER_PATH`와 그 폴더의 파일 상태 |
| "주문을 넣지 못했습니다" | 제안은 되살려 둔다. 다만 주문이 나간 뒤에 실패했을 수도 있으니, **보유 현황을 먼저 확인**하고 같은 번호로 다시 승인 |
| 예약해 둔 매매가 안 보임 | 자동 체결 예약(브로커가 스스로 건 것)과 승인 대기 제안(비서가 올린 것)은 다른 목록이다. 전자는 "지금 잔고", 후자는 `/승인`으로 본다 |
| 비용이 많이 나옴 | `.env`의 `ASSISTANT_EFFORT`를 `low`로 |
| `설정 오류: OBSIDIAN_VAULT...` | `.env`의 볼트 경로. 옵시디언에서 볼트 폴더 위치를 확인한다 |
| 자료를 넣었는데 안 보임 | `자료넣는곳` **바로 아래**에 있는지 (하위 폴더는 안 본다). 확장자가 `.pdf`가 맞는지 |
| "너무 큽니다 / 쪽수가 많습니다" | 한 번에 32MB·600쪽까지. 자료를 나눠서 넣는다 |
| "암호가 걸린 PDF" | 암호를 풀어 다시 저장한 뒤 넣는다 |

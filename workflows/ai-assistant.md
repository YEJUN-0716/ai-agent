# AI 업무 비서

## 목표

텔레그램(휴대폰)과 PC 브라우저에서 같은 비서에게 말을 건다.
비서는 주식 분석 결과를 읽고, 관심종목·메모를 기록하고, 가상 매매를 제안한다.

## 준비

1. `.env.example`을 `.env`로 복사하고 다음을 채운다.

   | 항목 | 무엇 |
   |---|---|
   | `ANTHROPIC_API_KEY` | Claude API 키 |
   | `TELEGRAM_BOT_TOKEN` | @BotFather에게 받은 봇 토큰 |
   | `TELEGRAM_ALLOWED_CHAT_IDS` | 내 chat_id. 여기 없는 사람은 봇이 무시한다 |
   | `STOCK_ANALYZER_PATH` | stock-analyzer 폴더 경로 |

   내 chat_id 확인법: 봇에게 아무 말이나 보낸 뒤
   `https://api.telegram.org/bot<토큰>/getUpdates` 를 브라우저로 연다.

2. `pip install -r requirements.txt`

## 실행

```
python server.py
```

- 웹 채팅: http://127.0.0.1:8765
- 텔레그램: 봇에게 그냥 말을 건다

둘은 같은 대화 기록을 본다. 폰에서 물어본 걸 PC에서 이어 물을 수 있다.

## 쓰는 법

평소처럼 물어보면 된다.

- "가상 브로커 지금 얼마야?"
- "최근 시그널 5개 보여줘"
- "엔비디아 관심종목에 넣어줘, 실적 발표 대기중이라고"
- "애플에 대해 메모 남겨줘: 가이던스 확인 후 재검토"
- "지난주에 내가 뭘 바꿨지?"

## 매매는 두 단계다

비서는 매매를 **제안만** 한다. 실행 권한이 없다.

1. "애플 100만원어치 사는 걸로 해줘" → 비서가 제안하고 승인 번호를 준다
2. `/승인 <번호>` → 그때 실제로 가상 브로커에 주문이 들어간다

| 명령 | 하는 일 |
|---|---|
| `/승인` | 대기 중인 제안 목록 보기 |
| `/승인 <번호>` | 승인해서 주문 넣기 |
| `/거절 <번호>` | 제안 버리기 |

채팅으로 "승인해서 바로 사줘"라고 해도 나가지 않는다. 승인 명령만이 주문을 낸다.
**실제 돈으로 하는 주문 기능은 이 시스템에 없다.**

## 무슨 일이 있었는지 확인하기

관심종목 변경·메모·매매 제안과 승인은 전부 `data/assistant/audit.log`에 남는다.
비서에게 "지난주에 뭘 바꿨지?"라고 물으면 읽어서 알려준다.

파일이 망가지는 일이 생기면 비서가 원본을 `.corrupt` 이름으로 보관하고
기록을 남긴다. 조용히 덮어쓰지 않는다.

## 도구를 하나 더 붙이려면

1. `tools/`에 파이썬 파일을 만든다. 함수는 `Settings`를 첫 인자로 받는다.
2. `tests/`에 테스트를 쓴다. 진짜 데이터에 의존하지 말고 `tmp_path`를 쓴다.
3. `assistant/brain.py`의 `_build_tools()`에 `@beta_tool` 함수를 더한다.
   도크스트링이 곧 비서가 읽는 설명서다 — 언제 쓰는 도구인지 명확히 쓴다.
4. **되돌릴 수 없는 행동이라면 실행 함수를 도구 목록에 넣지 않는다.**
   `tools/virtual_trade.py`처럼 제안과 승인을 분리하고, 승인은 창구가 부른다.

테스트를 쓸 때 한 가지: 항목이 하나뿐인 결과로 순서를 검증하면 정렬 코드를
지워도 통과한다. 이 프로젝트에서 실제로 겪은 일이다. 항목을 둘 이상 두고
정확한 순서를 확인한다.

## 고장났을 때

| 증상 | 확인할 것 |
|---|---|
| `설정 오류: ...` | `.env`의 해당 항목 |
| 웹을 폰에서 열고 싶다 | 안 된다. 웹은 이 PC 전용이고, `ASSISTANT_WEB_HOST`에 외부 주소를 넣으면 시작할 때 막는다. 폰에서는 텔레그램을 쓴다 |
| 답 끝에 "…여기서 멈췄습니다" | 비서가 도구를 너무 많이 쓰다 상한에 걸렸다. 질문을 좁혀서 다시 묻는다 |
| 텔레그램이 답을 안 함 | `TELEGRAM_ALLOWED_CHAT_IDS`에 내 chat_id가 있는지 |
| "주식 데이터를 읽지 못했습니다" | `STOCK_ANALYZER_PATH`와 그 폴더의 파일 상태 |
| "주문을 넣지 못했습니다" | 제안은 그대로 남아 있다. 원인을 고친 뒤 같은 번호로 다시 승인 |
| 비용이 많이 나옴 | `.env`의 `ASSISTANT_EFFORT`를 `low`로 |

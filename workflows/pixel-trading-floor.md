# PIXEL TRADING FLOOR

AI 에이전트 13명이 분석 → 토론 → 리스크 심사 → PM 승인을 거쳐 매매 판정을 내는
픽셀아트 트레이딩 오피스. **실제 주문은 하지 않는다.** 분석과 기록까지만 한다.

원본 가이드: `PIXEL-TRADING-FLOOR-가이드-v1.2.pdf` (바탕화면, 2026-07-30)

|---|---|

| 사무실 4개 방, 말풍선, 에이전트 콘솔, 판정 패널 | **된다** |
| 전광판·8비트 차트·멀티 거래소 표 | **된다 (합성값)** |
| 리포트 저장·목록·ZIP 다운로드·과거 판정 회고 | **된다** |
| ▶ ANALYZE 실전 분석 (클로드 호출) | **된다** |
| 실제 시세 API (Binance·Yahoo·환율·뉴스·공포탐욕) | **된다** |
| `/floor` 슬래시커맨드 — 세션 하나로 한 판 | **된다** |
| 검증 관문 — stock-analyzer 플랜 엔진이 판정을 기각할 수 있다 (알고리즘 모드만) | **된다** |

**데모(`?demo=1`)의 숫자는 전부 합성값, 실전의 숫자는 전부 실측이다.** 둘은 절대
섞이지 않는다. 실전에서 값을 못 가져오면 그 값을 빼거나 판을 접지, 합성으로 메우지
않는다. 화면 위 "시세 출처"가 그때그때 어디서 온 숫자인지 말해 준다.

## `/floor` — 브라우저 없이, 세션 하나로

```powershell
cd "C:\Users\1aass\OneDrive\Desktop\AI AGENT"
claude
```

세션 안에서:

```
/floor 하이닉스 scalp
/floor BTC algo
/floor 삼성전자 공격
/floor SK 하이닉스 scalp     ← 띄어 쓴 종목명도 받는다
```

모드를 안 적으면 알고리즘(13명)이다. 종목만 적을 때 주의.

**화면과 뭐가 다른가.** 판정 순서·규칙·검사·리포트 형식은 **한 글자도 다르지 않다.**
다른 건 누가 연기하느냐뿐이다. 화면은 발언마다 `claude` 프로세스를 새로 띄우고
그때마다 시세와 앞선 브리핑을 처음부터 다시 넘긴다. `/floor`는 지금 열려 있는
세션이 전원을 연기한다 — 프로세스 0개, 시세 조회 1회. 그래서 가장 적게 든다.

**리포트는 같은 서랍에 들어간다.** `/floor`로 낸 판정도 `reports/`에 쌓이고,
다음번 화면 분석의 "과거 판정 회고"에 그대로 올라온다. 반대도 마찬가지다.

**안 되는 것.** 픽셀 사무실 화면·말풍선·전광판은 안 뜬다. 그건 브라우저 몫이다.
`/floor`가 남기는 건 터미널 한 줄 요약과 리포트 파일이다.

### 속을 알고 싶다면

`/floor`는 두 명령을 감싼 것뿐이다. 직접 돌려도 된다.

```powershell
python -m floor.cli prep 하이닉스 scalp     # 시세를 한 번 찍어 얼리고 브리핑 팩 출력
python -m floor.cli save <상태파일> <브리핑파일>   # 검사하고 리포트로 남김
```

`prep`이 시세를 `.tmp/floor/`에 얼려 두는 건 취향이 아니다. 발언할 때마다 시세를
다시 조회하면 **13명이 서로 다른 가격을 보고 판정하게 된다.** 화면 경로가 스냅샷
하나를 전원에게 돌리는 것과 같은 규칙을 세션에서도 지키려고 얼린다.

`save`는 `-p` 러너와 **같은 검사 함수**(`claude_runner.parse_briefing`)를 지난다.
세션이 썼다는 이유로 느슨해지는 자리는 없다 — 모드에 없는 판정, 빠진 숫자, 어긋난
발언 순서, 모자란 인원수는 전부 여기서 거절당한다. 거절당하면 그 항목만 고쳐 다시
돌리는 게 맞다. 검사를 우회해 통과시키면 판정이 아니라 창작이 된다.

## 반드시 알고 고쳐야 할 것

### 1. 스캘핑 판정 기준은 원화 차트가 아니라 24시간 USDT 무기한이다

정규장 폭락일에는 원화 차트 변동성이 몇 배로 부풀려진다(실측 예: KRX 3.05% vs
무기한 1.20%). 그 값으로 재면 손절 폭이 커지고, 멀쩡한 셋업이 "청산 위험"으로
기각된다. 취향이 아니라 실측으로 나온 규칙이다.

코드에서는 `floor/agents.py`의 `BASIS_PERP`, `floor/demo.py`의 `_vol()`이 지킨다.

### 2. `ANTHROPIC_API_KEY`가 있으면 구독이 아니라 API로 과금된다

`floor/claude_runner.py`가 자식 프로세스 환경에서 이 변수를 **매번 벗겨서** 넘긴다.
사람이 기억해서 지키는 규칙은 언젠가 안 지켜지므로 코드에 박았고, 테스트가 잠근다.
그래도 다른 도구까지 안전한 건 아니니 창에 남아 있으면 지우는 편이 낫다.

```powershell
echo $env:ANTHROPIC_API_KEY                                   # 확인
$env:ANTHROPIC_API_KEY = $null                                # 이 창에서만 해제
[Environment]::SetEnvironmentVariable("ANTHROPIC_API_KEY", $null, "User")   # 영구
```

### 3. 공격 모드의 확신도는 판정이 아니라 연출이다

"무조건 방향을 골라라"는 규칙이 만든 숫자다. 50%대면 동전 던지기와 같다.
방향이 아니라 손절 레벨을 봐야 한다. 화면에도 그렇게 띄운다.

### 4. 탭비트 가격만 추정치다

나머지 4개 거래소(Binance·Bybit·OKX·Gate)는 실측이다. 탭비트만 직접 조회가 막혀
있어 그 4곳 평균으로 추정하고, 표에 "추정 · 직접 조회 불가"로 표시된다.
거래소 한 곳이 죽으면 그 줄이 통째로 빠진다 — 빈자리를 지어내지 않는다.

### 5. 저장된 리포트는 다음 판단의 입력이다

같은 종목을 다시 돌리면 지난 판정과 그 이후 가격 흐름이 콘솔의 "과거 판정 회고"에
들어간다. `reports/`를 비우면 회고가 사라진다.

### 6. 알고리즘 모드에는 클로드 위에 검증 관문이 있다

에이전트 13명이 낸 판정은 마지막에 **stock-analyzer 플랜 엔진**을 통과해야 한다.
방향(BUY/SELL)은 플로어가 정하지만 **진입·손절·목표 라인과 거부권은 엔진이 갖는다.**

엔진이 거는 게이트는 전부 실측으로 정해진 것이다:

- **손익비 1:2 미만 기각** — 이기는 판에서 잃는 판의 두 배를 못 벌면 승률이 반이어도
  남는 게 없다
- **저확신 숏 억제** — low 확신도 숏은 실측 기대값이 +0.16R 뿐이다
- **숏 레짐 필터** — 종목이 실제로 약세(50이평 아래 + 이평 하락)일 때만 숏 허용

기각되면 판정 카드가 빨갛게 잠기고, 리포트 머리말의 `action` 은 `HOLD` 로 적힌다.
**안 한 매매를 했다고 회고가 기억하지 않게 하기 위해서다.**

세 가지 상태가 있고 셋은 서로 다르다:

| 상태 | 뜻 |
|---|---|
| ✅ 통과 | 엔진이 유효한 셋업으로 인정했다 |
| ⛔ 기각 | 이 매매는 하지 않는다. 화면의 숫자는 실행 대상이 아니다 |
| ⚠️ 검사 못 함 | **통과가 아니다.** 엔진을 못 불렀거나 봉이 모자랐다 |

스캘핑·공격 모드에는 관문이 없다. 엔진은 일봉 ICT 구조 기반이라 15분봉 단타를
잴 수 없고, 못 재는 걸 잰 척하지 않는다.

관문이 돌려면 **stock-analyzer 와 같은 파이썬 환경**이어야 하고 `pandas` 가 필요하다.
위치는 환경변수 `STOCK_ANALYZER_PATH`, 기본값은 `~/stock-analyzer` 다.
못 찾으면 판은 그대로 끝나되 "검사 못 함"으로 남는다 — 검사기가 없다고 해서
매매가 승인된 것은 아니다.

## 파일

```
floor/
  agents.py         에이전트 13명·모드별 순서 (데이터만)
  market.py         심볼 해석 · demo_snapshot(합성) · live_snapshot(실측)
  demo.py           준비된 응답 러너 — 클로드 0회
  claude_runner.py  화면용 실전 러너 — claude -p 호출·JSON 검사·API키 차단
  cli.py            /floor 세션 러너 — prep(판 차리기)·save(검사·저장)
  pipeline.py       순서를 돌리고 사건을 내보냄. 러너를 인자로 받는다
  plan_gate.py      검증 관문 — stock-analyzer 플랜 엔진과의 유일한 이음매
  report.py         리포트 저장·목록·과거 판정 조회 (reports/ 경로도 여기)
  server.py         FastAPI 라우트·SSE
  static/           화면 (index.html · floor.css · floor.js)
.claude/commands/
  floor.md          /floor 슬래시커맨드 정의
reports/            분석 결과 (git 추적 안 함)
.tmp/floor/         얼린 판 상태 (버려도 되는 중간물)
tests/test_floor.py
```

**두 러너가 공유하는 것:** 프롬프트 조각(`facts`·`rules`·`shape`)과 응답 검사
(`parse_briefing`)는 `claude_runner.py`에 한 벌만 있고 `cli.py`가 가져다 쓴다.
한쪽에만 규칙을 더하거나 예외를 뚫으면 화면과 세션의 판정이 갈린다. 고칠 일이
생기면 공유하는 자리를 고친다.

## 고장났을 때

| 증상 | 해결 |
|---|---|
| 브라우저에 "연결할 수 없습니다" | 서버 창이 꺼진 상태. `python -m floor.server` 다시 실행 |
| 포트 8000 이미 사용 중 | 켜져 있던 창을 닫거나 `$env:PORT=8123` |
| "claude CLI 를 찾지 못했습니다" | 서버를 띄운 창에서 `claude --version`이 되는지 확인 |
| "시세를 가져오지 못했습니다" | 인터넷·해당 API 상태 문제. 종목 철자도 확인 (코인은 Binance에 상장된 것만) |
| "…형식을 어겼습니다"로 중단 | 클로드가 JSON을 두 번 깨뜨린 것. 그대로 다시 돌리면 대개 통과한다 |
| 실전이 너무 느리다 | 정상. 호출 하나가 프로세스 하나다. 급하면 스캘핑(5회)이나 `/floor` |
| `/floor`가 "브리핑이 N개입니다"로 거절 | 세션이 발언을 빠뜨렸거나 합쳤다. 빠진 사람만 채워 `save`를 다시 |
| `/floor`가 "발언 순서가 어긋났습니다" | 팩에 적힌 순서대로 다시 배열한다. 순서가 판정의 근거다 |
| `/floor`가 "판 상태가 깨졌습니다" | 얼린 시세 파일이 상했다. `prep`부터 다시 (`/floor`를 새로 치면 된다) |
| `/floor` 실행 때마다 승인을 물어본다 | `.claude/commands/floor.md`의 `allowed-tools`를 프로젝트 설정에서 허용 |
| 화면을 고쳤는데 안 바뀐다 | 정적 파일 캐시는 꺼져 있다. 새로고침으로 충분 |
| 콘솔 실행 시 `UnicodeEncodeError` | 윈도우 cp949 문제. `server.main()`이 stdout을 UTF-8로 돌린다 |
| 전광판이 안 보인다 | 하이닉스·삼성전자에서만 뜬다. 코인·미국주식엔 없다 |

## 검사

```powershell
python -m pytest tests/test_floor.py -q
```

69개. 호출 횟수(13/5/5), 무기한 기준 손절 폭, 공격 모드가 관망을 안 내는 것,
리포트 경로 차단, 회고 루프를 잠근다. 2단계에서 잠근 것:

- 실전 요청이 데모로 조용히 떨어지지 않는다
